# 레슨 개편 실행 계획 (코드 없음)

## 무엇을 하려는가
단원 설명을 승인된 미리보기 방식으로 바꿉니다. 미리보기는 장면이 하나씩 쌓이는 레슨이고, 사람이 직접 만지고 끌어 보는 부품이 들어갑니다. 이 레슨을 **JSON 데이터와 공용 부품**으로 앱 안에 구현합니다. 레슨에 들어가는 답은 지금의 sympy 검산을 똑같이 통과해야 합니다.
첫 결과물은 두 가지이고, 둘 다 끝나면 멈추고 사용자 확인을 받습니다.
- (a) 일차방정식 레슨을 미리보기 그대로 앱에서 재현
- (b) 곱의 미분 레슨을 드래그 그래프로 새로 작성

읽은 것과 확인한 사실은 이렇습니다.
- 커밋 author는 전부 ws-k(사용자 본인)라서 협업자 코드 제약은 없습니다.
- Node 24는 `.tsx`를 직접 import하지 못합니다(`ERR_UNKNOWN_FILE_EXTENSION`, 실측). 그래서 **검사기가 쓰는 코드는 전부 `.ts`**로 둡니다.
- 시뮬레이터에 iPhone Duo, iPad Air 11·13, iPad mini, iPad Pro가 있습니다.

## A. 핵심 설계 결정

### A1. 레슨 형식 (`src/lesson/types.ts`, 순수 `.ts`)
```ts
interface Lesson { minutes: number; scenes: Scene[] }          // 장면 6~10개
type Base = { id: string; chip?: string; title: string; lead?: string; after?: string }
type Scene =
 | Base & { kind:'intro'; meta?: string[] }
 | Base & { kind:'question'; widget?: WidgetSpec; choices:{label:string; check:string; feedback?:string}[];
            answer:number; answerCheck:string; reveal:string; thoughts?:string[] }
 | Base & { kind:'explore'; widget: WidgetSpec; gate?: boolean }      // 손으로 해 보기, 지름길
 | Base & { kind:'terms'; terms:{term:string; body:string}[]; aside?:string }
 | Base & { kind:'spot'; items: SpotItem[] }                          // 틀린 곳 찾기
 | Base & { kind:'solve'; items: (Example & { placeholder?:string })[] } // 기존 Example 재사용
 | Base & { kind:'summary'; points:string[]; next?:string }
interface SpotItem { prompt:string; tokens:{tex:string; bad?:true}[]; fix:{tex:string; body:string};
  verify:{ mode:'identity'|'equivalent'; from?:string; wrong:string; fixed:string } }
interface WidgetSpec { type:string; params:Record<string,unknown>; alt?:string }  // alt = 끌기 대체 안내
```
- **'지름길'은 따로 종류를 두지 않습니다.** `explore` 장면에 `chip:"지름길"`만 붙입니다. 장면 종류는 교육적 역할로 나누고, 인터랙션의 차이는 부품이 맡습니다.
- 모든 글 칸은 지금의 `Rich` 형식(`$...$`)을 그대로 씁니다. 미리보기의 강조(`hl`)와 굵게를 표현하려면 `renderRich`에 강조 옵션(`**굵게**`, `==강조==`)을 **옵션으로 추가**합니다. 새 렌더러는 만들지 않습니다.
- **부품 지정**은 `{type, params}`로 합니다. 등록부는 둘로 나눕니다.
  - `src/lesson/widgets/specs.ts`(.ts): 형식 검사 `validate(params)`와 검산 항목 생성 `checks(params)`
  - `src/lesson/widgets/index.tsx`: 화면 부품
  - 형식 검사 도우미 `num/str/expr/arr/oneOf`는 직접 짭니다. zod 같은 라이브러리를 새로 들이지 않습니다.
- **탈출구**: `type:"custom:<unitId>.<name>"`로 지정하고, 화면 부품은 `src/lesson/custom/<unitId>.tsx`, 형식 검사는 `<unitId>.spec.ts`에 둡니다(검사가 없으면 등록이 안 되게 막음). 쓸 수 있는 기준은 세 가지입니다.
  - (1) 기존 부품에 옵션을 더해도 표현이 안 될 때
  - (2) 다른 단원에서 쓸 일이 없을 때
  - (3) **두 번째 단원이 같은 것을 원하면 공용 부품으로 올리고 옵션화합니다.** 복제는 금지입니다(저장소 규칙).
- **기존 Unit과의 관계**
  - `Unit.lesson?`을 추가하고, `concept`·`examples`는 선택 칸으로 바꿉니다.
  - 레슨이 있는 단원은 **레슨이 concept+examples를 대체**합니다. 예제 2~3개는 `solve` 장면으로 옮기고, `formulas`는 단원 홈의 공식 카드에 남깁니다.
  - **연습문제 30개(기초 15/표준 10/수능형 5)와 복습(SRS)은 그대로 둡니다.**
  - 검사 규칙은 "lesson이 있거나, concept+examples가 있거나" 둘 중 하나입니다. lesson이 있으면 `solve` 항목이 합쳐서 2~3개여야 합니다.
  - 기존 concept·examples 글은 6단계 확인 전까지 JSON에 남겨 둡니다. UI에서만 숨깁니다.

### A2. 검증
- `content-check.ts`에 `validateLesson` 결과를 붙입니다. 장면 id 중복, 빈 칸, 모든 글 칸의 KaTeX strict 검사(지금의 `texOk`), 부품 `validate`를 봅니다. 검산 항목은 아래처럼 만듭니다.
  - **question**: `{answerType:'choice', answer:String(answer+1), check:answerCheck, choiceChecks:choices[].check}`. 지금 `verify.py`의 choice 분기는 보기 개수와 상관없이 동작하므로 고칠 것이 없습니다. 보기 5개 규칙은 **문제에만** 적용하고, 장면은 2~5개를 허용합니다. 정답이 아닌 보기에는 `feedback`이 필수입니다.
  - **solve**: 기존 `checkAnswerShape`와 `item()`을 재사용합니다.
  - **spot**(새 kind `spot`):
    - `identity`이면 `fixed`의 양변 차가 0이고 `wrong`은 0이 아니어야 합니다.
    - `equivalent`이면 `from`과 `fixed`의 해집합이 같고 `wrong`의 해집합은 달라야 합니다.
    - 어느 토큰이 `bad`인지는 기계로 못 봅니다. 리뷰 항목으로 둡니다.
  - **부품이 만든 항목**: `checks(params)`가 돌려줍니다.
    - 예: balance는 `solve(Eq(left,right))`와 목표값을 비교합니다. 버튼 연산은 "양쪽" 연산이면 동치, "한쪽만" 연산이면 동치가 아니어야 합니다(새 kind `equiv`).
    - termDrag는 옮기기 전과 후의 식이 동치여야 합니다.
  - **식 일치 검사**(새 kind `parity`): 그래프를 그리는 TS 계산기(`src/lesson/expr.ts`)와 sympy가 **같은 식을 같은 값으로 계산하는지** 확인합니다. content-check가 부품 안의 모든 식을 표본 점 7~11개에서 TS로 계산해 그 값을 함께 내보내고, verify.py가 sympy로 다시 계산해 상대오차 1e-9 이내인지 봅니다. 실수가 아닌 값은 양쪽 다 "정의 안 됨"이어야 통과입니다.
  - **식 문법(공통)**: 숫자, 선언된 변수, `+ - * / **`, 괄호, `sin cos tan exp log sqrt Abs pi E`만 씁니다. `^`는 금지입니다(sympy에서는 XOR). 계산기는 이 밖의 것을 만나면 거부합니다.
- **좌표평면 찍기·그리기 답의 검산** (`coord` 부품의 `task`, 새 kind `plot`). 격자에 붙여(스냅) 찍으므로 좌표가 유리수입니다. 그래서 **허용 오차 0**을 기본으로 합니다.

| task | 앱에서 채점 | sympy가 검사하는 것 |
|---|---|---|
| `point`(점 (a,b)에 찍기) | 일치 | `x`·`y` 검산식(계산식만, 숫자 그대로 금지)이 화면 범위 안이고 격자 위인가 |
| `pointsOn`(곡선 위 점 k개 찍기) | 점마다 `y==f(x)`, x 중복 없음, k개 | 범위 안 격자점 가운데 조건을 만족하는 점이 **k개 이상 있는가**(풀 수 있는 문제인가) |
| `line`(기울기 m / 점 P를 지나는 / y절편 c인 직선, 두 손잡이로 그리기) | 두 점에서 기울기·통과점 계산 | 조건을 만족하는 직선이 범위 안 **격자점 2개를 지나는가** |
| `connect`(찍은 점 잇기로 곡선 그리기) | `pointsOn`과 같고, x순으로 이어 꺾은선 표시 | 위와 같음 |
| `sketch`(손으로 곡선 긋기, 7단계) | 21개 x에서 표본을 떠 85% 이상이 `tol` 안이고 x범위를 80% 이상 덮으면 통과 | `tol ≤ 격자 간격`(형식 검사), 대상 곡선이 구간 안에서 유한하고 화면 안인가 |

- 채점 함수는 `src/lesson/grade.ts`(.ts)에 두고 TDD로 만듭니다. 문턱값 85%·80%는 기기 시험 뒤에 조정합니다.

### A3. 부품 라이브러리 (1차, 103단원을 덮는 최소 집합)
그래프와 도형은 **외부 라이브러리 없이 SVG로 직접** 그립니다. 새 의존성은 없습니다. 공용 바탕은 네 가지입니다.
- `svg/plane.ts`: 세계 좌표와 화면 좌표 변환, 눈금
- `drag.ts`: 순수 계산(스냅, 경계 넘기 판정, 범위 제한, 키보드 한 칸 이동)
- `useDrag`
- `Handle.tsx`: 보이는 점은 14px, 누르는 영역은 56px

| 부품 | 주요 매개변수 | 주로 쓰는 단원 |
|---|---|---|
| `balance` 저울 | left/right 항, 미지수 아이콘, ops[{label,op,value,side}], relation(`=`/`<`) | 일차방정식, 부등식, 연립, 문자와 식 |
| `termDrag` 항 끌기 | lhs/rhs 토큰, movable, rule(`flipSign`/`flipIneq`) | 이항, 부등식, 이차방정식 정리 |
| `numberLine` 수직선 | min/max/step, 끌 수 있는 점, 점프 화살표, 구간, 자료 점과 평균·중앙값 표시, task | 정수·유리수, 절댓값, 부등식의 해, 제곱근 위치, 대푯값·산포도 |
| `fraction` 분수 조각 | 분모 슬라이더, 조각 끌어 합치기, mode(비교/덧셈/뺄셈/곱 넓이/나눗셈), 목표 | 초등 분수 4단원, 소수, 비·비례 |
| `areaModel` 넓이 모형·대수 타일 | 가로·세로 항, 끌어 늘리기(Δ)로 띠 2개+모서리 표시, 타일 끌어 직사각형 만들기 | 곱셈, 분배, 곱셈공식, 인수분해, **곱의 미분** |
| `coord` 좌표평면 | view·격자, controls(슬라이더), curves(y=f(x)·매개변수식·수열 점), points(drag: free/onCurve/xOnly, snap), 덧그림(secant, tangent, riemann, area, vectors, segments, region), readouts, mode(`explore`/`plot`/`line`/`connect`/`sketch`), task | 좌표, 일차·이차·지수·로그·삼각·유리·무리함수, 도형의 이동, 원·이차곡선, 극한~정적분 전부, 수열, 벡터, 산점도 |
| `unitCircle` 단위원 | 각 단위(도/라디안), 점 돌리기, 특수각 스냅, sin·cos 투영, 그래프로 펼치기, 두 번째 각 | 삼각비, 삼각함수, 덧셈정리, sinx/x |
| `shape` 도형 판 | 끌 수 있는 꼭짓점(제약: 선분 위·원 위), 다각형·원, 길이·각·넓이 표시, 잘라 옮기기 | 넓이, 기본 도형, 삼각형·사각형, 닮음, 피타고라스, 원, 사인·코사인법칙, 이차곡선의 정의 |
| `count` 경우의 수 | 물건, 칸, mode(나열/고르기/수형도/중복), 파스칼, 벤 | 경우의 수, 순열·조합, 이항정리, 집합 |
| `simulate` 확률 실험 | 동전·주사위·주머니·분포, 시행 횟수, 히스토그램과 이론값 비교, 시드 rng(`generators/rng.ts` 재사용) | 확률, 조건부, 이산·이항·정규분포, 추정 |
| `table` 표·영수증 (정적) | 행·열, `?` 칸 | 질문 장면의 도입, 자료 정리 |
| `solid` 입체 (뒤로 미룸) | 꼭짓점·면, 끌어 회전(정사영), 전개도 | 직육면체, 입체도형, 공간도형·좌표 |

- **슬라이더는 따로 부품을 두지 않습니다.** 모든 부품의 `controls` 옵션으로 둡니다.
- 만드는 순서는 "그 부품이 필요한 첫 단원"을 따릅니다. 4단계에서 balance·termDrag, 5단계에서 coord(필요한 옵션만)·areaModel을 만들고, 나머지는 7단계 이후에 만듭니다.
- **드래그 공통 규칙**
  - Pointer Events를 쓰고 `setPointerCapture`로 붙잡습니다. 손가락·펜·마우스를 모두 받습니다. 레슨 화면에는 필기가 없으므로 펜으로도 끌 수 있습니다.
  - `touch-action:none`은 **손잡이와 그리기 영역에만** 겁니다. 그래야 페이지 스크롤이 살아 있습니다.
  - 끄는 동안에는 React 상태를 매 프레임 바꾸지 않습니다. requestAnimationFrame 한 번에 ref로 SVG 속성과 표시 값만 직접 고치고, 손을 뗄 때 상태에 반영합니다(전역 규칙 "애니메이션은 렌더 바깥에서").
  - **모든 끌기 목표에는 탭 대체가 있어야 합니다.** 미리보기의 "끌기 어려우면 눌러서 보내기", ± 버튼이 그 예입니다.
  - 손잡이는 `role="slider"`, `aria-valuenow`, 방향키 한 칸 이동을 갖고, 결과 문구는 `aria-live`로 읽힙니다.
  - 시스템의 '동작 줄이기'가 켜져 있으면 포물선 이동·튐·축하 효과를 끄고 바로 제자리로 옮깁니다.

### A4. 앱 화면 개편 (기기: iPhone Duo + iPad)
- **디자인 토큰**: 미리보기의 `:root` 토큰을 그대로 가져옵니다(라이트·다크, `data-theme`).
  - 글꼴은 **시스템 고딕**(`-apple-system`, `Apple SD Gothic Neo`)입니다. Gothic A1 웹폰트는 오프라인 앱이라 넣지 않습니다. 명조 글꼴 미결 사안은 이것으로 사라집니다.
  - 버튼은 최소 48px, 끄는 손잡이의 누르는 영역은 56px입니다. **전 과정 같은 값**이고, 과정마다 따로 두지 않습니다.
- **레이아웃 기준은 그대로** 둡니다: `layoutMode`는 너비 800 이상이고 너비가 높이의 1.2배 이상이면 2단입니다. iPad 가로(1133~1376×744~1032)는 2단, iPad 세로와 분할 화면은 1단이 되어 별도 처리 없이 덮입니다. 실측 크기는 1단계에서 기록합니다.
  - **레슨은 화면 모양과 상관없이 늘 한 줄**로 둡니다. 내용 폭은 최대 640px, 부품 카드는 최대 720px입니다.
  - 높이가 낮은 화면(Duo 가로 585, 접음 580)에서는 부품 높이를 `50svh` 이하로 묶고, 하단 '계속하기' 버튼 영역을 낮게 합니다.
- **화면 구성**
  - 홈: 오늘 할 일과 이어서 하기(레슨 또는 문제)
  - 지도: 과정별 단원 카드에 레슨 완료 여부와 문제 진행률
  - **단원 홈**(새 화면, `#/unit/<id>`): 레슨 시작·이어하기, 공식 카드, 수준별 문제 목록
  - **레슨**(`#/lesson/<id>`): 진행 막대, 장면 쌓기, 하단 고정 '계속하기'. 진행 상황은 `lesson:<unitId>` 키로 저장합니다.
  - **문제 화면**(`#/unit/<id>/<pid>`)
    - 넓은 화면: 왼쪽 문제 카드, 오른쪽 풀이 노트
    - 좁은 화면: 문제 카드 아래 '풀이 노트'를 펼침 또는 탭으로 엽니다.
    - 이전 주소 `?side=note`도 계속 해석합니다.
- **필기는 그대로**: `src/ink/*`와 `InkPage.tsx`는 고치지 않습니다. 놓이는 자리만 바뀝니다(풀이 노트 = 지금의 공책 쪽, 자동으로 늘어남).
- **design.md에서 바뀌는 결정** (10장 "진짜 책처럼"을 일부 폐기)
  - 폐기: 종이색·명조·쪽 번호·가운데 접힌 자국, 개념·예제 '쪽'과 그 쪽의 필기, 쪽 넘김으로 개념에서 문제로 가는 흐름

### A5. 전 연령 원칙과 유치함 방지
- **기본 원칙**
  - 재미는 꾸밈이 아니라 **직접 만져서 알아내는 손맛**과 깔끔한 화면에서 나옵니다.
  - 기준은 승인된 미리보기의 톤입니다.
  - 디자인 체계는 **전 과정 하나**입니다. 초등이라고 색·글꼴·모양을 바꾸지 않습니다.
- **금지**(기본값): 캐릭터, 말풍선, 이모지, 반말, 과한 보상 연출(별·레벨업·팡파르).
- **칭찬은 짧고 절제합니다.** 체크 표시, 색 변화, "정답이에요" 한 줄, 그리고 미리보기 수준의 작은 효과(정답일 때만, 동작 줄이기면 끔)까지만 씁니다.
- **과정별로 다른 것은 글과 소재뿐**입니다. 존댓말 "~해요"와 담백한 톤은 같습니다.
  - 초등: 리드 문장 2개 이하, 한 문장 40자 안팎, 그림이 먼저 나오고 글이 뒤, 장면 6~7개
  - 중등 이상: 장면 7~9개, 고등부터는 요약 장면에 "수능에서는" 한 줄을 넣을 수 있습니다.
  - 소재는 아이와 어른이 둘 다 아는 것(간식, 장보기, 요리, 운동, 여행, 용돈, 게임 점수)으로 고릅니다.
  - 초·중등에서는 성인 전용 소재(술·대출·세금·도박)를 쓰지 않습니다. 실존 브랜드도 쓰지 않습니다.
- **아이도 혼자 쓸 수 있게**
  - 모든 장면(용어·요약 장면 제외)에 손 조작이 1개 이상 있습니다.
  - 틀리면 그 보기가 왜 틀렸는지 바로 보여 줍니다.
  - 숫자 입력은 시스템 키보드 대신 기존 `NumPad`를 재사용합니다.
  - 끌기에는 반드시 탭 대체가 있습니다.
- **어린이·어른 분리 선택지 비교** (103단원 기준)

| 안 | 내용 | 작업량 | 검산 영향 | 유지보수 |
|---|---|---|---|---|
| (A) 한 가지 톤 | 위 원칙대로 레슨 103개 | 기준(1배) | 없음 | 최소 |
| (B) 학습자 모드 | 설정의 어린이/어른에 따라 같은 장면의 **글 칸만** `kid` 변형으로 바꿔 끼움. 인터랙션·숫자·문제·디자인은 공유. 범위는 초등~중3 41단원 | 41단원 글쓰기 +30~40% | 숫자를 공유하면 없음. 소재를 바꾸면서 숫자까지 바꾸면 해당 항목이 2배 | 두 글을 함께 고쳐야 함. 앱은 설정 1개와 대체 로직 |
| (C) 별도 코스 | 어린이용 레슨(+문제)을 따로 | 41단원 +100%(문제까지 하면 그 이상) | 2배 | 최대. 진행 기록도 갈라지고 내용이 어긋나기 쉬움 |

**추천은 (A)**입니다. 미리보기 톤이 이미 중립적이고, 유치함을 피하는 가장 확실한 길입니다. (B)는 나중에 붙여도 기존 데이터와 충돌하지 않습니다. 글 칸 옆에 선택 칸 `kid?`를 더하기만 하면 되기 때문입니다. 그래서 7단계의 초등 시범 레슨을 아이가 써 본 뒤에 다시 판단합니다.

## C. content-guide.md 갱신안 (핵심)
1. **독자**: 초등생~성인. 존댓말 "~해요", 담백한 톤(A5 원칙, 금지 목록 포함). 연습문제 풀이 말투는 Q2 답에 따릅니다.
2. **장면 흐름 기본형**:
   - 순서: 도입 → 오늘의 질문(이미 아는 직관을 꺼냄) → 손으로 해 보기(규칙 발견) → 이름 붙이기(용어는 **발견한 뒤에**) → 지름길 또는 두 번째 해 보기 → 틀린 곳 찾기(실제로 자주 하는 실수 2개) → 직접 풀기 2~3개(힌트와 풀이 한 단계씩) → 한 장 요약(3~4줄)
   - 한 장면에는 생각 하나만 담습니다.
   - 공식에는 장면 안에서 "왜"를 보여 줍니다(글보다 조작으로).
3. **인터랙션 고르는 기준**:
   - 손으로 바꿔 봤을 때 **결과가 눈에 보이게 달라지는 것**을 고릅니다.
   - 따지는 순서: 이미 있는 부품의 옵션 → 옵션 추가 → custom(A1의 기준).
   - 끄는 것은 "옮기면 의미가 바뀌는 것"(항, 점, 조각)에만 씁니다.
   - 단순히 고르는 것은 탭으로 합니다.
   - 끌기에는 탭 대체가 반드시 있습니다.
4. **검산**: 장면 안의 모든 정답·보기·틀린 곳·부품 목표·찍기 과제는 검산식이 필수입니다. 글 속에 결과 숫자를 쓸 때는 검산된 칸의 값과 같아야 합니다(리뷰 항목).
5. **단원당 작업량**(기존 부품만 쓰는 경우):
   - 장면 7±2개, 부품 설정 1~3개, 검산 항목 +8~12개, 커밋 1개
   - 새 부품이 필요하면 +1~2커밋
   - custom 부품은 전체의 10% 이하가 목표입니다.

4. 계산기와 sympy가 경계 값(log 음수, 0 나누기, 큰 지수)에서 똑같이 "정의 안 됨"으로 처리하는가. parity 테스트로 확인합니다.
5. biome의 a11y 규칙이 SVG 손잡이의 포인터 처리기를 막는가. 막으면 `role`을 부여해 해결합니다. 규칙을 끄지는 않습니다.
