### 2-2. 단원 적용은 두 가지로 나눈다

| | 전환형 | 추가형 |
|---|---|---|
| 뜻 | 부품의 **조작이 바뀌어** 지금 글이 화면과 어긋나게 되는 것(P5) | 새 **옵션**이 생겨 요청한 단원이 쓰면 더 좋아지는 것 |
| 예 | count 끌기, simulate 직접 던지기, 수직선 점프, split 자르는 선, 분수 겹쳐 대 보기, 꼼수 식 없애기, 실생활로 그림이 통째로 바뀌는 장면 | 막대, 선분·세로선·이름, 도형판 점선·단위, 새 읽는 값·과제, 틀린 곳 찾기 기호 |
| 언제 | **그 부품과 같은 단계에서 바로**(세로 조각) | **모아서 단원당 1~2회**(3-아, 4-마) — 같은 단원을 조각마다 다시 열지 않게 |

같은 단원 JSON 을 두 묶음이 동시에 열지 않습니다. 부품 작업은 단원 JSON 이 아니라 자기 테스트의 시험 장면으로 확인하므로 단원 적용과 동시에 가도 됩니다.

조작이 바뀌는 부품은 **기존 칸 이름·뜻이 그대로 읽히게** 만듭니다(지금 JSON 이 형식 검사를 통과). 칸을 꼭 바꿔야 하면 메인이 합칠 때 옮깁니다.

### 2-3. QA 배분

- **code-reviewer 는 코드를 합칠 때만**(부품·검산·스크립트). 단원 JSON 묶음은 **verifier**(형식 검사·검산·`verify:diff` 설명·화면 측정)만.
- 코드 묶음: 실패하는 테스트 먼저(TDD) → typecheck·lint·test → code-reviewer → verifier.
- 모든 묶음 공통 합격선(P6): `verify:diff` 로 달라진 검산 항목이 목록으로 나오고 하나하나 설명됨 · 전체 검산 통과(메인이 합칠 때 1회) · **장면 id 사라짐 0** · (0-나 뒤부터) **기존 문제 id 사라짐·내용 바뀜 0**.
