# 레슨 부품 매개변수 (단원 작성자용)

레슨 장면의 `widget: { "type": "...", "params": { ... } }` 에 넣는 값입니다. 모르는 칸·없는 참조는 형식 검사(`npm run verify`)에서 오류가 납니다. 채점·화면에 쓰는 값은 모두 검산 항목으로 내보내져 sympy 가 다시 계산합니다.

식 글자는 공통 문법입니다: 숫자, 변수, `+ - * / **`, 괄호, `sin cos tan exp log sqrt Abs pi E`. `^` 는 쓰지 않습니다(sympy 에서 다른 뜻). 곱셈 기호 `*` 는 빼지 않습니다(`3*x`).

---

## coord — 좌표평면

"이름 붙은 객체 + 참조" 목록으로 그립니다.

```json
{
  "mode": "explore",
  "x": { "min": 0, "max": 1.6, "step": "1/5" },
  "y": { "min": 0, "max": 8, "step": 1 },
  "objects": [
    { "id": "fg", "curve": "x**2*x**3", "label": "$y=x^2\\cdot x^3$" },
    { "id": "P", "point": { "on": "fg", "x": 1 }, "name": "P" },
    { "id": "Q", "point": { "on": "fg", "x": 1.5, "drag": "x", "snap": "1/20" }, "name": "Q" },
    { "secant": ["P", "Q"] },
    { "readout": "slope(P,Q)", "label": "할선 PQ 의 기울기" }
  ],
  "goal": { "approach": ["Q", "P"] },
  "intro": "처음 안내", "done": "목표를 이뤘을 때"
}
```

| 칸 | 뜻 |
|---|---|
| `mode` | `explore`(점 끌기·슬라이더) · `plot`(빈 칸 눌러 점 찍기, 끌어 옮기기, 눌러 지우기) · `connect`(찍은 점을 x 순으로 이음) · `line`(두 손잡이로 직선) · `sketch`(‘그리기 시작’ 뒤 손으로 긋기) |
| `x`, `y` | `min`·`max`·`step`(격자 칸 간격). 수 또는 식 글자(`"2*pi"`, `"pi/6"`). 칸은 40칸 이하. 선택: `name`(축 이름)·`unit`(단위) — 아래 '축 이름·단위' |
| `equal` | `true` 면 **축척 같게**: 가로·세로 한 칸의 화면 길이를 같게(모자란 쪽에 맞추고 남는 폭은 가운데로). 지도·밭처럼 모양이 곧 정보일 때만 쓰고, 글에서 '한 칸 = 10 m' 같은 말은 이 옵션을 켠 장면에서만 씁니다. 가장 좁은 화면(상자 298×200)에서 그림이 가로 125·세로 80px(기본 그림 250×160 의 절반)보다 작아지면 형식 오류 — 가로·세로 범위 비가 큰 축척 같게가 그림을 납작하게 만든다(밭은 150×160) |
| `sliders` | `[{id, min, max, step, value, label, exclude?}]` 1~3개. `id` 는 한 글자(a·b·c·d·h·k·m·n·p·q·r·s·t)이고 곡선 식에 그대로 씁니다. `exclude: [1]` 은 닿지 않게 건너뛰는 값(밑 a≠1 등, 칸 위 값·처음 값이 아닌 것, 3개까지) — 끌어서 닿으면 움직이던 쪽으로 한 칸 더 갑니다. **목표가 보는 슬라이더**는 가장 좁은 화면에서 한 칸이 7px 이상이어야 합니다: 줄 길이 = 298 − 이름 글자 폭 − 가장 긴 값 글자 폭 − 틈 20 − 손잡이 20(글자 폭은 실측 기반 어림, 한글 16·숫자 11px). 이름이 길거나(`조각 수 $n$` 은 30칸에서 5.8px) 값이 소수(−1.75)면 줄이 짧아집니다 |
| `intro`, `done` | 글(Rich, `{{값}}` 가능) |
| `start` | line 모드 두 손잡이 처음 자리 `[[x,y],[x,y]]` (생략하면 가로 1/4·3/4, 가운데 줄) |

**objects** (앞에서 만든 이름만 가리킬 수 있습니다)

| 객체 | 모양 |
|---|---|
| 곡선 | `{id, curve:"식(x)", label?, tone?: main·soft·accent, hide?: true}` — `label` 은 그림 아래 범례(Rich). `hide` 는 아래 '숨긴 정답' |
| 구간만 그린 곡선 · 조각 함수 | `{id, curve:"식", x:"[0,3]"}` · `{id, curve:[{y:"x+1", x:"[0,1)"}, {y:"4-x", x:"[1,2]"}]}` — 아래 '조각 함수' |
| 곡선 위 점 | `{id, point:{on:"곡선 id", x, drag?: none·x, snap?, range?}, name?}` — y 는 곡선에서 계산. `x` 는 `snap`(기본: x 칸 간격)의 배수 |
| 칸 위 점 | `{id, point:{x, y, drag?: none·xy·x, range?}, name?, hide?: true}` — 칸 간격의 배수. `drag: "x"` 는 **가로로만**(세로 칸 그대로, 위·아래 키도 가로로) — 막대·넓이의 끝을 가로축 위에서 끌 때. `hide` 는 끄지 않는 점(목표 점)만 |
| 따라오는 점 | `{id, point:{x:"x(P)", y:0}}` · `{id, point:{on:"g", x:"x(P)"}}` · `{id, point:{x:"h", y:0}}` — 좌표가 슬라이더·앞 점 좌표의 식. 끌지 않음 — 아래 '따라오는 점' |
| 선분 · 화살표 | `{segment:[끝, 끝]}` · `{arrow:[꼬리, 머리]}`, 선택 `tone`·`label` — 아래 '선분·화살표' |
| 할선 | `{secant:["P","Q"]}` — 두 점이 같은 곡선 위 같은 자리에 오면 **접선으로 바뀝니다**(극한) |
| 접선 | `{tangent:{on:"곡선", at:"점"}}` — 기울기는 앱이 곡선을 기호 미분해서 계산 |
| 읽는 값 | `{readout:"slope(P,Q) · deriv(f,P) · x(P) · y(P) · value(a) · roots(f) · meet(f,g) · sums(R) · big(R) · small(R) · gap(R) · net(F) · abs(F) · area(B) · prob(A) · cover(C) · 슬라이더 식", label, digits?: 0~4 (기본 2, area·prob 은 4), frac?: true}` — 아래 표. `frac` 이면 유리수 값을 분수로(1/2, −2/3) 보이고 무리수면 digits 자리 소수 |
| 칠하기 | `{id?, fill:{top, bottom?, x:[a, b 또는 점]}, look?, sign?, name?, nameAt?, hide?}` — 아래 '칠하기' |
| 구분구적 | `{id, rects:{of:"곡선", x:[a,b], n:"슬라이더 id" 또는 수}}` — 아래 '구분구적' |
| 막대(히스토그램·이항분포) | `{id, bars:{x, h} · {data, from, w} · {binom:[n,p]}, sel?, density?}, label?` — 아래 '통계 막대' |
| 정규분포 곡선 | `{id, curve:{normal:[m, s]}, label?, tone?}` — 평균·표준편차로 밀도함수를 만듦. 아래 '정규분포 넓이' |
| 정규분포 넓이 | `{id, shade:{of:"정규분포 곡선", x:[a, b]}}` — 아래 '정규분포 넓이' |
| 신뢰구간 여러 개 | `{id, ci:{m, sd, n, z, draws}}` — 아래 '신뢰구간' |

**끄는 x 범위** `range: [a, b]` (요청 127·139): 끄는 점만. 양 끝 포함, 끄는 칸(곡선 위 점은 `snap`, 칸 위 점은 x 칸) 위의 값이고 축 안, 두 칸 이상, 처음 자리를 품어야 하며, 곡선 위 점이면 양 끝에서 곡선이 정의돼야 합니다. 옛 다가가기 목표(`approach`)도 이 범위 안에서 목표 점에 `within` 안으로 닿는 칸이 있어야 합니다. 끌기·방향키·◀▶ 버튼·목표 검산(닿는 상태 늘어놓기)이 모두 이 칸만 봅니다 — `{"on": "s", "x": 4, "drag": "x", "snap": 1, "range": [1, 12]}` 이면 P 가 O(x=0)에 겹치는 '크기 0' 자리가 아예 없어 목표가 그 자리를 세지 않습니다. 칸 위 점(xy)은 x 만 막고 y 는 그대로.

끄는 손잡이는 점이 y 범위 밖으로 나가도 **그림 테두리 안에 붙고 흐린 색**(`data-off`)이 됩니다(요청 141 — 점은 잘려 안 보여도 손잡이를 잡아 다시 끌어 올 수 있게, 흐려서 '점이 여기 있다'로 읽히지 않게). 화면 낭독기 값 글은 실제 좌표 그대로입니다.

`name` 은 그림 위 점 이름표(요청 19·112): 한 글자(P, Q)·여러 글자(`출발`·`정상`·`그저께`)·프라임(`A′` — 옛 단원의 ASCII `A'` 도 그대로)·아래 첨자(`P₁`). 폭은 한글 13·그 밖 9px 로 세어 **54px 이하**(한글 4자·영문 6자 — 가장 좁은 화면 그림 폭 250px 에서 점 둘레를 넓게 덮지 않게). 그림 글자라 수식(`$`·`\`·`{}`)·앞뒤 빈칸은 형식 오류. 이름표 자리는 점의 오른쪽 위 → 왼쪽 위 → 오른쪽 아래 → 왼쪽 아래 → 위 → 아래 중 그림 안이고 다른 이름표·점과 겹치지 않는 첫 자리(`labels.ts`, 끄는 동안에도 같이 움직임). 무거운 형식 검사가 **가장 좁은 화면·처음 자리에서 이름표가 그림 밖이거나 서로 겹치면** 오류를 냅니다(이름을 짧게 하거나 점 사이를 넓게). 같은 읽는 값을 두 줄 두면 형식 오류(숫자가 겹치고 검산 항목 이름도 겹침).

**읽는 값**

| 글자 | 값 |
|---|---|
| `slope(P,Q)` | 직선 PQ 의 기울기. 같은 곡선 위 두 점이 겹치면 접선 기울기(극한) |
| `deriv(f,P)` | 곡선 f 의 P 에서의 미분계수 |
| `x(P)` · `y(P)` | 점의 좌표 |
| `value(a)` | 슬라이더 값 |
| `roots(f)` | f(x)=0 의 **서로 다른 실근 개수**(중근은 1개, 정수로 보임). 곡선이 x 의 다항식이고, 곡선에 쓴 슬라이더의 `min`·`step` 이 유리수여야 함. 실수 전체에서 셉니다(화면 범위 밖 근도) |
| `meet(f,g)` | 두 곡선의 교점 개수 = f(x)=g(x) 의 서로 다른 실근 개수. 조건은 `roots` 와 같음 |
| `sums(R)` | 구분구적 R 의 **작은 어림 ~ 큰 어림** 한 줄(초록 ~ 노랑 글자, 조각 색과 짝). 목표에는 못 씀(값이 둘) |
| `big(R)` · `small(R)` · `gap(R)` | 큰 어림 · 작은 어림 · 두 어림의 차이(정확한 분수). 목표에 쓸 수 있음 |
| `net(F)` | 칠하기 F 의 **부호 있는 합** $\int_a^b(\text{위}-\text{아래})\,dx$(정확한 분수). 속도 → 집 기준 위치. 목표에 쓸 수 있음 |
| `abs(F)` | 칠하기 F 의 **부호 뗀 합** $\int_a^b|\text{위}-\text{아래}|\,dx$ — 위·아래가 바뀌는 곳에서 끊어 조각마다 부호를 떼고 더함. 속도 → 걸은 거리, 두 곡선 사이 넓이. **목표에는 못 씀**(끝이 끄는 점이면 끊는 곳이 상태마다 달라 검산이 한 식으로 되풀이 못 함 — `net` 으로) |
| `area(B)` | 막대 B 의 **고른 막대**(`sel`, 없으면 모든 막대) 넓이 합 — 정확한 분수. 이항분포면 확률 $P(a\le X\le b)$, 히스토그램이면 도수×계급의 크기(`density` 면 상대도수의 합). 기본 4자리, 반올림이 값을 바꾸면 `≈`. **목표에는 아직 못 씀** |
| `prob(A)` | 정규분포 넓이 A $=\Phi(\frac{b-m}{s})-\Phi(\frac{a-m}{s})$. 무리수라 기본 4자리(표준정규분포표 자리)로 반올림해 `≈`(끝이 평균·끝없음뿐이면 `0.5`·`1` 처럼 정확히). `frac` 은 형식 오류(무리수). **목표에는 아직 못 씀** |
| `cover(C)` | 신뢰구간 C 중 모평균 m 을 품은 구간 수(정수). **목표에는 아직 못 씀** |
| 슬라이더 식 | 위 꼴이 아니면 슬라이더 이름으로 계산하는 식(`"b**2-4*a*c"` — 판별식). `x` 는 못 씀 |

개수(`roots`·`meet`)는 분수 계산과 스투름 열로 정확히 셉니다 — 소수로 세면 중근 자리에서 0개·2개를 오가서.

조각 넓이 합(`sums`·`big`·`small`·`gap`)과 칠한 영역의 합(`net`·`abs`)은 분수로 정확히 계산해 `digits` 자리로 반올림해 보이고, 반올림이 값을 바꾸면 앞에 `≈` 를 붙입니다(`≈ 285 ~ 315 m²`). 넓이 숫자는 보통 `digits: 0`.

**축 이름·단위** (조각 ③-가)

```json
"x": { "min": 0, "max": 30, "step": 10, "unit": "m" },
"y": { "min": -2, "max": 30, "step": 10, "unit": "m" }
```

- 눈금 숫자는 **세계 좌표 그대로**입니다. 실제 길이를 눈금에 적으려면 좌표를 실제 단위로 둡니다(밭: 가로 0~30 m, 강가 $y=x^2/30$ — 눈금 0·10·20·30). 식과 눈금이 같은 수라 학습자가 식에 넣어 볼 수 있습니다.
- 축 끝 글자: `name`·`unit` 이 있으면 `시간(분)`, 단위만 있으면 `(m)`. 가로는 마지막 눈금 오른쪽, 세로는 눈금 숫자 열 위. 글자 수가 아니라 **합친 폭이 79px 이하**(11px 굵게 한글 11·그 밖 6.5px 로 셈 — 한글 7자 남짓, `속력(km/시)` 65.5px 는 됨). 가로축 글자는 그만큼 그림 폭을 줄이므로, 가장 좁은 화면 기본 그림 폭의 1/3 을 넘게 먹지 않게 한 값.
- 목표가 보는 곡선 위 점의 끄는 칸은 가장 좁은 화면의 **실제 그림 폭**(축 끝 글자 자리·축척 같게로 줄어든 폭)에서 한 칸 8px 이상 — 단위 `(m)` 만 붙어도 그림 폭이 250 → 226.5px 로 줄어 30칸이 안 됩니다.
- **읽는 값의 단위는 축에서 저절로** 정해집니다(읽는 값마다 적지 않으니 어긋날 수 없음): `x(P)` → 가로 단위, `y(P)` → 세로 단위, `slope`·`deriv` → `세로/가로`(m/분, 가로·세로 단위가 같으면 단위 없음 — m/m 이 아니라 그냥 비율), 조각 넓이 합 → 가로×세로(같으면 `m²`). 슬라이더 값·식 값·개수는 단위가 없습니다.
- 저절로 만든 글자가 어색하면(시간 × km/시 = km) **세로축에** `areaUnit`·`slopeUnit` 을 한 번 적습니다. 넓이 읽는 값이 있는데 가로·세로 단위가 다르거나 한쪽에만 있고 `areaUnit` 이 없으면 형식 오류(기울기도 한쪽에만 있으면 오류).

**칠하기** `{id?, fill:{top, bottom?, x:[a, b 또는 점]}, look?, sign?, name?, nameAt?, hide?}`

```json
{ "fill": { "top": 30, "bottom": "f", "x": [0, 30] }, "look": "water", "name": "강" },
{ "fill": { "top": "f", "x": [0, 30] }, "look": "soil", "name": "밭" },
{ "fill": { "top": 0, "bottom": -2, "x": [0, 30] }, "look": "road", "name": "길" }
```

- `top`·`bottom` 은 앞에 나온 곡선 이름 또는 수(수평선 y=값). `bottom` 을 빼면 가로축(y=0). 두 곡선 사이도 같은 꼴(`top: "g", bottom: "f"`). `x` 는 화면 안.
- `look`: `plain`(기본, 옅은 파랑) · `soil`(흙, 밭고랑 무늬) · `water`(물결 무늬) · `road`(단색 회색). **무늬는 넓은 영역에만** — 좁은 띠(길)는 `road` 처럼 단색으로.
- 칠하기는 **격자 아래**에 깔리고(칸을 셀 수 있게), 구분구적 조각은 격자 위·곡선 아래, `name` 이름표는 맨 위에 그립니다(객체 순서와 상관없이). 이름표 자리는 칠한 영역의 무게중심, 어긋나면 `nameAt: [x, y]`. 이름표는 6자 이하.
- `hide: true` 는 **맞힌 뒤 칠하기**: 목표·과제를 이루기 전에는 경로와 이름표 자리를 그리지 않습니다(숨긴 정답과 같은 규칙 — 목표나 과제가 없으면 형식 오류).
- 색은 앱 토큰(`--soil`·`--water`·`--road` 와 무늬 선 `-line`, 다크 모드 포함).
- **끝이 점을 따라감**: `x: [0, "B"]` 처럼 끝 자리에 앞에 나온 점 이름을 적으면 그 점의 x 까지 칠합니다(시각을 끌면 그때까지). 끝만 되고, 점이 닿는 가장 왼쪽이 시작보다 왼쪽이거나 가장 오른쪽이 시작 이하면 형식 오류.
- **부호별 칠하기** `sign: true`: 위 경계가 아래보다 위인 곳(+)은 파랑, 아래인 곳(−)은 빨강(`fillr pos`·`fillr neg`). 색이 곧 부호라 `look` 은 `plain` 만. 부호별 칠하기·끝 점을 따라가는 칠하기에 `name` 을 달면 `nameAt` 필수(꼬인 다각형·끄는 동안 무게중심이 튀거나 흔들림). 색 토큰은 `--fill-pos`·`--fill-neg`.
- **넓이 읽기** `id`: 이름을 붙이면 읽는 값 `net(F)`·`abs(F)` 가 이 영역을 가리킵니다. 그때만 위−아래가 **x 의 다항식**(슬라이더 없음)이고 구간 안에서 부호가 바뀌는 곳이 **모두 유리수**여야 합니다(유리근 정리로 찾아 스투름 개수와 견줌 — 구간 안 무리수 근이면 형식 오류). 숨긴 칠하기(`hide`)는 읽지 못합니다(맞히기 전에 넓이가 드러남).
- 검산: 이름 없는 칠하기는 숫자를 보이지 않아 항목이 없습니다. `net`·`abs` 읽는 값은 **끝이 닿는 모든 자리**에서 앱의 분수 = sympy `integrate`(abs 는 sympy 가 `real_roots` 로 따로 찾은 근에서 끊어 조각마다 `Abs`, 위−아래는 `nsimplify` 로 분수 계수) 항목을 냅니다(`칠하기 F 부호 뗀 합 x=3`).

```json
{ "id": "v", "curve": "4-2*x" },
{ "id": "B", "point": { "on": "v", "x": 1, "drag": "x", "snap": "1/4" } },
{ "id": "F", "fill": { "top": "v", "x": [0, "B"] }, "sign": true },
{ "readout": "net(F)", "label": "집 기준 위치" },
{ "readout": "abs(F)", "label": "걸은 거리" }
```

**구분구적** `{id, rects:{of, x:[a,b], n}}`

```json
"sliders": [{ "id": "n", "min": 1, "max": 30, "step": 1, "value": 1, "label": "$n$" }],
"objects": [
  { "id": "f", "curve": "x**2/30" },
  { "id": "R", "rects": { "of": "f", "x": [0, 30], "n": "n" } },
  { "readout": "sums(R)", "label": "넓이 어림", "digits": 0 }
],
"goal": { "visit": { "of": "gap(R)", "at": [180, 90, 30] }, "hint": "…" }
```

- [a,b] 를 폭이 같은 n 조각으로 나눠 **큰 어림(노랑)과 작은 어림(초록)을 함께** 그립니다. 큰 어림을 아래, 작은 어림을 위에 그려서 위로 삐져나온 노란 띠가 곧 두 어림의 차이입니다. 높이가 0 인 조각은 그리지 않습니다.
- 곡선은 **x 의 다항식**이고 슬라이더를 쓰지 않으며, **[a,b] 안(끝점 제외)에 기울기 0 인 곳이 없어야** 합니다(도함수의 구간 안 실근을 스투름 열로 정확히 셈 — 끝점에서만 기울기 0 인 것은 괜찮음). 꺾이는 곡선이면 양 끝 높이가 큰 어림·작은 어림이 아니라서 형식 오류이고, x³ 처럼 멈췄다 다시 오르는 곡선도 보수적으로 막습니다. 오르는 곡선은 큰 어림 = 오른쪽 끝 높이, 내리는 곡선은 왼쪽 끝.
- 곡선은 [a,b] 에서 **가로축 위(높이 ≥ 0)** 여야 합니다: 높이가 음수인 조각은 아래로 그려져 노란 띠·초록 조각의 위아래가 뒤집힙니다(양 끝 중 낮은 쪽이 0 아래면 형식 오류).
- `x` 의 끝은 유리수(두 합을 분수로 정확히). `n` 은 1 이상의 정수만 닿는 슬라이더 또는 고정 수(1~200).
- **조각 폭 상한**: 가장 좁은 화면(상자 298×200)에서 n 이 가장 클 때 조각 폭이 4px 이상이어야 합니다(테두리에 가려 색이 안 보이지 않게). 밭(가로 30 m 를 30조각, 축척 같게)은 5px.
- 검산: 닿는 모든 n 의 두 합 = sympy summation, 넓이 = sympy integrate, 그리고 **큰·작은 배정의 독립 검증** — 앱이 낸 두 어림 값을 그대로 적고 sympy 가 따로 적분한 넓이가 닿는 모든 n 에서 `작은 어림 ≤ 넓이 ≤ 큰 어림` 인지(배정이 뒤바뀌면 summation 항목은 같이 맞아도 이 항목이 잡음).
- 끄는 동안 React 를 다시 그리지 않습니다: 큰·작은 어림은 경로 두 개라 n 이 바뀌어도 그릴 목록 항목(key)이 같고, 경로 글자·읽는 값 글자만 바꿔 넣습니다.

**통계 막대** `{id, bars:{…}, label?}` (2-가 — 요청 84·99, 히스토그램 21)

```json
"x": { "min": "-1/2", "max": "21/2", "step": 1 },
"sliders": [
  { "id": "n", "min": 1, "max": 10, "step": 1, "value": 4, "label": "시행 횟수 $n$" },
  { "id": "p", "min": "1/10", "max": "9/10", "step": "1/10", "value": "1/2", "label": "성공 확률 $p$" }
],
"objects": [
  { "id": "K", "point": { "x": 2, "y": 0, "drag": "x" }, "name": "K" },
  { "id": "B", "bars": { "binom": ["n", "p"], "sel": [null, "K"] } },
  { "readout": "area(B)", "label": "$P(X\\le k)$" }
]
```

- 막대의 출처는 셋 중 하나만:
  - `{x:[계급 끝…], h:[도수…]}` — 계급 끝(차례로 커짐)과 도수(0 이상, 계급 수만큼)를 그대로.
  - `{data:[자료…], from, w}` — 자료(200개까지)를 `from` 부터 계급의 크기 `w`(수 또는 **슬라이더**)로 나눠 셉니다. 계급은 **왼쪽 닫힘** `[a, a+w)`. `from` 보다 작은 자료는 형식 오류. `w` 를 슬라이더로 두면 같은 자료를 다시 묶어 보는 장면이 됩니다.
  - `{binom:[n, p]}` — 이항분포 $B(n,p)$. 막대 k 는 **가운데 k·폭 1**(넓이 = 높이 = 확률). `n` 은 1 이상의 정수(수 또는 슬라이더), `p` 는 0~1 의 유리수(수 또는 유리수 칸 슬라이더). 그래서 x 축은 −1/2 부터 n+1/2 까지 품어야 합니다(`"min": "-1/2"`).
- `sel: [a, b]` — **가운데가 a~b 안인 막대**(양 끝 포함)를 노랑으로 칠하고 `area` 가 그 넓이 합을 냅니다. 끝은 수, 앞에 나온 **점 이름**(그 점의 x — 끌어서 구간을 고름), 또는 `null`(끝없음). $P(X\le k)$ 는 `[null, "K"]`, $P(X\ge k)$ 는 `["K", null]`. 끝 점은 보통 가로축 위 칸 점 `drag: "x"`. **이항분포의 끝 점은 모든 막대(정수)에 설 수 있어야** 합니다: 끄는 칸이 1 을 나누어떨어지게(1·1/2), 곡선 위 점이면 가장 좁은 화면에서 한 칸 8px 이상(모자라면 끌기가 칸을 묶어 막대를 건너뜀) — 아니면 형식 오류. x 축이 40칸까지라 **끝 점으로 고르는 장면은 n ≤ 39**.
- `density: true` — 높이 = 도수 / (총도수 × 폭)(상대도수 밀도). 넓이 합이 1 이라 **정규분포 곡선과 겹쳐** 볼 수 있습니다. 이항분포에는 못 씀(이미 확률).
- **막대 + 곡선 겹치기**: 곡선 객체를 함께 두면 됩니다. 막대는 늘 곡선 아래 층에 그립니다. 이항분포의 정규 근사는 `{id:"N", curve:{normal:["n*p", "sqrt(n*p*(1-p))"]}}`. `label` 이 있으면 범례에 네모 견본으로 나옵니다.
- 형식 오류: **n 상한 60**(가장 좁은 화면 그림 폭 250px 에 막대 61개가 4.1px — 막대 폭 하한), 가장 좁은 화면에서 **가장 좁은 막대가 4px 미만**, **화면 밖 막대**(닿는 모든 n·계급 크기에서 — 잘린 막대는 넓이를 견줄 수 없음), `y min` 이 0 보다 큼(막대 아래가 잘림), 계급 40개 넘음, **가장 높은 막대가 그림 위로 잘림**(닿는 모든 n·p·계급 크기에서 — 슬라이더가 있으면 무거운 검사에서), `area` 가 바뀌는 상태(슬라이더 칸 × 끝 점 칸)가 **2000 넘음**(n 20 × p 9 × K 21 = 3780 은 넘음 — 하나를 고정, 읽는 값이 없어도 막대가 바뀌는 슬라이더 칸이 2000 넘으면 오류), **p 의 분모가 10000 넘음**(확률의 분모가 (p 의 분모)ⁿ 이라 수로 바꿀 때 넘침), `density` 인데 **총도수 0**, 이항분포에 `from`·`w`, `area` 를 `frac` 으로 보일 때 닿는 어느 상태에서든 **분수 글자가 14자 넘음**(접은 화면 읽는 값 칸 — B(10, 3/10) 처럼 분모가 큰 장면은 소수로).
- 검산: 이항분포 막대 높이 parity(`막대 B 높이` — 앱 분수 = sympy `binomial`, 닿는 (n,p,k) 를 고르게 400 점까지), 자료 히스토그램은 계급 크기마다 `막대 D 도수 h=5`(sympy 가 `[F+iW, F+(i+1)W)` 로 따로 셈), `density` 면 상태마다 `막대 H 밀도 높이`(앱의 분수 = sympy 가 도수/(총도수×폭)로 따로 셈), `area` 는 **닿는 모든 상태**마다 `막대 B 넓이 합 n=10, p=3/10, K=3` — 화면 숫자 글자 = sympy 합을 같은 자리로 반올림(approx), `frac` 이면 분수 그대로.

**정규분포 넓이** `{id, curve:{normal:[m, s]}}` + `{id, shade:{of, x:[a, b]}}` + `{readout:"prob(A)"}` (2-가 — 요청 99)

```json
{ "id": "N", "curve": { "normal": [0, 1] } },
{ "id": "P", "point": { "on": "N", "x": 1, "drag": "x", "snap": "1/5", "range": [-3, 3] }, "name": "P" },
{ "id": "A", "shade": { "of": "N", "x": [null, "P"] } },
{ "readout": "prob(A)", "label": "$P(Z\\le z)$" }
```

- 정규분포 곡선은 식을 손으로 적지 않고 `normal:[m, s]`(수 또는 슬라이더 식, `x` 는 못 씀)로 만듭니다 — 넓이가 그 m·s 를 그대로 씁니다. 표준편차는 닿는 모든 슬라이더 값에서 **0 보다 커야** 합니다(이항분포 근사면 `p` 슬라이더가 0·1 에 닿지 않게). 구간(`x`)은 못 붙임. 점이 곡선 위를 달릴 수 있습니다.
- `shade` 는 정규분포 곡선 아래 a~b 를 노랑으로(격자 아래 층) 칠합니다. 끝은 수·앞에 나온 점·`null`(끝없음). 화면 밖은 그림 끝에서 자르고 넓이는 끝까지 셉니다. 끝이 시작 이하면 넓이 0.
- **반올림 규칙**: 넓이는 무리수라 분수로 쥘 수 없습니다. `digits`(기본 4 — 표준정규분포표 자리)로 반올림해 `≈ 0.8413` 처럼 보이고, 끝이 평균·끝없음뿐일 때만 `0.5`·`1` 로 정확히 보입니다. 끝의 0 은 뗍니다(`0.975`). 0.5 는 0 에서 먼 쪽으로(검산 approx 와 같은 규칙). 앱의 erf 는 양의 항만 있는 급수 하나(6 보다 크면 1)로 1e-15 안팎까지 맞춥니다.
- 끄는 칸은 곡선 위 점의 50칸 상한을 따릅니다(−4~4 를 0.1 칸은 80칸이라 안 됨 — 0.2 칸이나 범위를 좁게). 두 끝을 모두 끌면 상태가 곱으로 늘어 2000 상한에 닿기 쉽습니다(41 × 41 = 1681 은 됨).
- 검산: 닿는 모든 상태(m·s 슬라이더 × 끝 점 칸)마다 `정규분포 넓이 A P=1`(approx — 화면 글자 = sympy `erf` 를 같은 자리로 반올림). **새 검산 종류는 없습니다**(기존 approx 재사용).

**신뢰구간 여러 개** `{id, ci:{m, sd, n, z, draws}}` + `{readout:"cover(C)"}` (2-가 — 요청 99)

```json
"x": { "min": 20, "max": 80, "step": 10 },
"y": { "min": 0, "max": 21, "step": 5, "name": "표본" },
"sliders": [
  { "id": "n", "min": 1, "max": 25, "step": 1, "value": 4, "label": "표본 크기 $n$" },
  { "id": "c", "min": 1, "max": 3, "step": "1/2", "value": 2, "label": "$z$" }
],
"objects": [
  { "id": "C", "ci": { "m": 50, "sd": 10, "n": "n", "z": "c", "draws": [0.3, -1.2, 2.1, 0.8] } },
  { "readout": "cover(C)", "label": "평균을 품은 구간" }
]
```

- 표본 k(1부터)의 구간 $[\bar x-z\frac{\sigma}{\sqrt n},\ \bar x+z\frac{\sigma}{\sqrt n}]$ 을 **y=k 줄**에 가로 막대로 그립니다. 모평균을 품은 구간은 파랑, 못 품은 구간은 빨강, 모평균은 점선 세로선, 표본평균은 짧은 세로 금.
- `draws` 는 **표준화한 표본평균** $u=\frac{\bar x-m}{\sigma/\sqrt n}$ (유리수, |u| ≤ 6, 40개까지). 실제 $\bar x$ 를 적지 않는 까닭: n 슬라이더를 움직여도 같은 표본이라 $\bar x=m+u\frac{\sigma}{\sqrt n}$ — n 을 키우면 **구간이 좁아질 뿐 품는지(|u| ≤ z)는 그대로**입니다(신뢰도는 n 이 아니라 z 가 정함). `z` 를 슬라이더로 두면 품은 수가 바뀝니다.
- `m`·`sd` 는 유리수(m 은 화면 안, sd > 0), `n` 은 1 이상의 정수, `z` > 0(각각 수 또는 유리수 칸 슬라이더). 슬라이더 이름은 한 글자 규칙이라 z 는 다른 글자(`c` 등)로.
- 형식 오류: 줄이 그림 밖(**y 가 1/2 이하 ~ k+1/2 이상을 품어야**), 가장 좁은 화면에서 **줄 간격 5px 미만**.
- 검산: z 값마다 `신뢰구간 C 덮는 수 c=2` — 앱의 |u| ≤ z 셈 = sympy 가 구간 끝($m\pm$…)으로 따로 센 값, 그리고 n 을 양 끝 포함 5칸 골라 그 값이 모두 같은지(다르면 '좁아질 뿐 그대로'가 거짓).

**끄는 동안**: 막대·고른 막대·정규분포 넓이·구간(품음·못 품음·금·세로선)은 모두 경로 몇 개라 n·p·계급 크기·끝 점이 바뀌어도 그릴 목록 항목(key)이 같고, 경로 글자·읽는 값 글자만 바꿔 넣습니다(React 렌더 0회).

**조각 함수·구간만 그리기** (요청 76·82 — 한 기제: 구간만 그리기는 조각이 하나)

```json
{ "id": "f", "curve": [ { "y": "x+1", "x": "[0,1)" }, { "y": "4-x", "x": "[1,2]" } ] },
{ "id": "g", "curve": "x**2-2*x", "x": "[0,3]" },
{ "id": "h", "curve": [ { "y": "(x**2-1)/(x-1)", "x": "[-2,1)" }, { "y": "(x**2-1)/(x-1)", "x": "(1,2]" }, { "y": "1", "x": "[1,1]" } ] }
```

- 구간은 **글자** `"[a,b)"` — 대괄호 = 닫힘(그 값을 가짐), 둥근괄호 = 열림. 배열 `[a,b]` 은 받지 않습니다(열림을 빠뜨려도 조용히 닫힘이 되지 않게). `[a,a]` 는 한 점(구멍 자리에 따로 정한 함숫값). 끝은 수·식(`pi/2`).
- 값은 x 가 든 조각의 식, **어느 조각에도 없으면 정의 안 됨** — 곡선 위 점은 그 자리로 끌리지 않습니다. 경계에서는 닫힌 쪽 조각의 값(위 `f` 는 f(1)=3).
- **끝 표시는 저절로**: 닫힌 끝은 찬 점 ●, 열린 끝은 빈 점 ○(곡선 색, 빈 점 안은 카드 바탕색). 같은 경계에서 닫힌 끝과 열린 끝이 **같은 높이면(이어짐) 둘 다 그리지 않습니다** — 연속인 곳에 점이 찍히지 않게. 식이 열린 끝에서 정의 안 되면(`(x²−1)/(x−1)` 의 x=1) 다가가는 자리에 빈 점을 그립니다. **화면 끝(x 축의 min·max)과 같은 끝은 그리지 않습니다** — 그림 밖으로 이어지는 것과 구분되지 않으므로, 끝 점을 보이려면 x 축을 한 칸 넓히세요.
- 형식 오류: 조각이 겹침(경계를 두 조각이 다 닫음), 화면과 길이 있게 겹치지 않는 조각(닫힌 끝 한 점만 화면 끝에 걸친 것 포함), **화면 끝·밖의 한 점 조각**(찬 점이 안 보임), 열린 한 점 `(a,a]`, 왼쪽 끝 > 오른쪽 끝, 닫힌 끝에서 식이 정의 안 됨, 조각 7개 이상, 배열 꼴 `curve` 에 바깥 `x`. 끝 표시는 곡선이 쓰는 **슬라이더의 모든 칸 값**에서 봅니다: 보이는 표시가 **y 범위 밖**이면, 가장 좁은 화면에서 서로 다른 끝 자리끼리 **가로 13px 미만**이거나 같은 x 의 ○·● 가 **세로 13px 미만**이면 오류(표시 바깥 지름 12.4px — 겹치면 어느 쪽이 닫혔는지 안 보임). 같은 자리의 같은 표시(구멍 양쪽 ○○)는 괜찮습니다.
- 쓸 수 있는 곳: 곡선 위 점·할선·접선·`x`·`y`·`slope`·`deriv` 읽는 값·목표·숨김(`hide`). **아직 못 쓰는 곳**(형식 오류): `roots`·`meet`, 칠하기 경계, 구분구적, 과제 곡선(pointsOn·sketch·line tangent) — 식 하나를 x 전체에서 다루는 계산이라 조각의 정의역을 모릅니다.
- 접선·`deriv`·겹친 할선(미분이 쓰이는 곳)은 그 x 의 조각을 미분합니다. 그래서 **미분이 쓰이는 조각 곡선 위 점이 매끄럽지 않은 끝에 닿으면 형식 오류**입니다: 정의역 끝(화면 끝이어도 한쪽만 이어짐)·한 점 조각·끊긴 경계(양쪽 값이 다름)·꺾인 점(양쪽 미분이 다름). 앱도 sympy `diff(Piecewise)` 도 같은 한쪽 미분을 내 검산으로는 못 잡기 때문입니다. 끄는 점은 `range`·`snap` 으로 그 칸을 빼세요(곡선의 슬라이더 모든 칸 값에서 봄). 매끄럽게 이어진 경계는 괜찮습니다.
- 곡선 위 끄는 점의 방향키·◀▶ 는 곡선이 정의 안 된 칸(구멍)을 같은 방향 다음 칸으로 건너뜁니다(끝까지 없으면 제자리).
- 검산: `곡선 f 계산` 은 sympy `Piecewise((식, 조건), …)` 하나로 고른 점 9개 + 화면 안 조각 끝 전부(경계에서 어느 조각을 쓰는지, 구간 밖은 양쪽 다 '정의 안 됨'), 미분이 쓰이면 `곡선 f 미분`(diff(Piecewise)), 열린 끝이 화면 안에 있는 조각마다 `곡선 f 조각1 빈 점`(그 조각 식의 끝 값 = 빈 점 높이). 모두 기존 parity 종류입니다. 식이 열린 끝에서 정의 안 되는 경우의 빈 점 높이(극한)는 그리기용 어림이라 검산 항목이 없습니다.

**선분·화살표** (요청 108)

```json
{ "id": "O", "point": { "x": 0, "y": 0 }, "name": "O" },
{ "id": "A", "point": { "x": 2, "y": 1 }, "name": "A" },
{ "arrow": ["O", "A"], "tone": "soft", "label": "$\\vec a=(2,1)$" },
{ "arrow": ["O", ["2*k", "k"]], "tone": "accent", "label": "$k\\vec a$" },
{ "segment": [[3, 0], [3, 3]] }
```

- 끝은 **앞에 나온 점 이름**(끄는 점이면 따라 움직임) 또는 **좌표 `[x, y]`** — 수나 슬라이더 이름만 쓴 식(`"2*k"`). `x` 는 못 씀. 세로 선분·세로 벡터도 됩니다(꼼수 곡선으로는 못 그리던 것).
- 화살표는 머리 쪽에 화살촉을 그리고, 화살대는 화살촉 밑에서 끝납니다. **머리가 점이면 화살촉 끝을 점 가장자리까지 물립니다**(끄는 점 11.5px — 손잡이에 가려지지 않게, 고정 점 6px). 길이가 0 이면(k=0) 숨깁니다. `tone`·`label` 은 곡선과 같고, `label` 이 있으면 범례에 나옵니다.
- 형식 오류: **화면 밖 끝**(좌표 끝·끌 수 없는 칸 위 점·끌 수 없는 곡선 위 점 끝을, 끝이 쓰는 슬라이더의 **모든 칸 값**에서 봄 — 화살촉이 잘리면 방향이 안 보임), 늘 같은 두 끝, **같은 선분·화살표 두 번**(끝을 좌표로 풀어 견줌 — `'O'` 와 `[0,0]`, `'4/2'` 와 `2` 는 같은 끝, 선분은 방향 반대도 같음, 화살표는 반대 방향이면 다른 것), 가장 좁은 화면에서 **(머리 점 물림을 뺀) 16px 보다 짧은 0 아닌 화살표**(화살촉만 남음). 끄는 점 끝은 자리가 손에 달려 이 검사에서 빠집니다.
- 검산: 슬라이더 식 끝 좌표마다 `화살표 O→(2*k,k) 머리 x`(선분은 `끝1`·`끝2`) — 슬라이더의 모든 칸 값에서 앱 계산 = sympy(parity). 점 끝·고정 수 끝은 항목이 없습니다(점은 점 쪽에서, 수는 글자 그대로).

**따라오는 점** (요청 50·129·137)

```json
"sliders": [{ "id": "h", "min": -3, "max": 3, "step": 1, "value": 0, "label": "$h$" }],
"objects": [
  { "id": "g", "curve": "(x-h)**2" },
  { "id": "V", "point": { "x": "h", "y": 0 }, "name": "꼭짓점" },
  { "id": "F", "curve": "x**2+h" },
  { "id": "P", "point": { "on": "F", "x": -1, "drag": "x" }, "name": "P" },
  { "id": "R", "point": { "on": "g", "x": "x(P)" }, "name": "R" },
  { "id": "H", "point": { "x": "x(P)", "y": 0 }, "name": "H" },
  { "segment": ["P", "H"] }
]
```

- 좌표에 **슬라이더 이름**이나 **앞에 나온 점의 좌표 `x(P)`·`y(P)`** 를 쓰면 그 값을 따라 움직이는 점이 됩니다. 칸 위 점은 `x`·`y` 둘 다(한쪽은 수여도 됨 — 수선의 발 `{x:"x(P)", y:0}`), 곡선 위 점은 `x` 만(y 는 곡선에서 — 다른 곡선 위 같은 세로줄 `{on:"g", x:"x(P)"}`). 식은 `+ - * / **`·괄호·`sqrt` 등 공통 문법이고 `x` 는 못 씀(곡선이 아니라 한 자리). 따라오는 점을 다시 따라올 수 있고(`x(H)/2`), 식 하나에 점 좌표는 5개까지.
- **끌지 않습니다**: `drag`·`snap`·`range`·`hide` 를 붙이면 형식 오류(식이 자리를 정하므로 손잡이가 있으면 '끌어도 되돌아가는 점'). 칸 위가 아니어도 됩니다. 조각·구간 곡선 위에는 아직 못 둡니다.
- 가리킬 수 있는 곳: 선분·화살표 끝, 할선·접선, 읽는 값 `x`·`y`·`slope`·`deriv`(그 읽는 값을 보는 목표는 따라오는 점을 움직이는 끄는 점·슬라이더를 늘어놓음). **못 쓰는 곳**(형식 오류): 칠하기 끝·막대 고르기 끝·정규분포 넓이 끝·목표의 점(`place`·`approach`) — 점이 닿는 칸을 늘어놓아 검산하는 곳이라.
- **화면 밖**: 슬라이더만 따라오는 점은 닿는 모든 슬라이더 칸에서 정의되고 그림 안이어야 합니다(형식 오류 — `h=3` 처럼 어느 칸인지 알려 줌). 끄는 점을 따라오는 점은 자리가 손에 달려 있어, 그림 밖으로 나가면 **점과 이름표를 함께 숨깁니다**(이름표만 그림 안에 홀로 떠 있지 않게).
- 끄는 동안 React 를 다시 그리지 않습니다: 점·이름표 항목은 늘 같은 key 이고 자리·숨김만 바꿔 넣습니다.
- 검산: 좌표마다 `따라오는 점 R x`·`따라오는 점 R y`(parity) — 그 점을 움직이는 끄는 점 칸 × 슬라이더 칸(400 상태 넘으면 고르게 덜어 냄)에서 앱 좌표 = sympy(가리키는 점의 검산 글자 — 끄는 점은 상태 기호 `pt_P_x` — 를 식에 넣어 따로 계산). 수 그대로인 좌표는 항목이 없습니다.

**숨긴 정답** `hide: true`: 목표·과제를 이루기 전에는 그 곡선(범례 포함)·목표 점을 그리지 않고, 이루면 그립니다(손그리기의 정답 곡선, 평균값 정리의 목표 점 등). 숨긴 객체는 **목표·과제만** 가리킬 수 있습니다 — 다른 점·접선·읽는 값이 가리키면 숨긴 자리가 드러나므로 형식 오류. 숨긴 동안에는 그릴 목록에 자리(좌표)가 아예 없습니다.

**goal** (explore 만) — 목표는 진행을 막지 않습니다('계속하기'는 늘 열림). 이루면 `done` 글·장면 완료·숨긴 정답 공개·결론 글 공개(장면 `afterGoal`). 판정은 **손을 뗀 자리에서만**(끄는 도중 지나간 자리는 세지 않음, 방향키·◀▶ 버튼·슬라이더 키는 마지막 입력 뒤 0.6초 멈추거나 포커스가 떠날 때 한 번), 숨긴 정답에 가까워져도 글·색이 바뀌지 않습니다. 손을 8번 떼도 못 이루면 `hint` 를 보입니다.

| 목표 | 모양 | 이룬 때 |
|---|---|---|
| 여러 곳 가 보기 | `{"visit": {"of": "읽는 값", "at": [60, 90, 120]}, "hint": "…"}` | 읽는 값이 `at` 의 값마다 한 번씩 됨(2~6곳). 아래에 "3곳 중 2곳" |
| 값 맞추기 | `{"value": {"of": "roots(f)", "is": 1, "places"?: 2}, "hint": "…"}` | 읽는 값이 `is` 가 되는 자리 `places`(기본 1)곳. `is` 는 수 또는 다른 읽는 값(`"slope(P,Q)"` — 접선 기울기 = 평균 기울기). 개수끼리는 견주지 않음 |
| 점 자리 | `{"place": {"point": "P", "x": {value, check}, "y": {value, check}}, "hint": "…"}` | 끄는 점이 그 칸에(곡선 위 점과 가로로만 끄는 칸 위 점 `drag:"x"` 는 `x` 만 — 가장 좁은 화면에서 한 칸 8px 이상). 답이라 `check`(문제 조건으로 계산하는 sympy 식) 필수 |
| (옛) 다가가기 | `{"approach": ["끄는 점","목표 점"], "within"?}` | 끄는 점이 목표 점에 `within`(기본 0 = 겹침) 안으로. `hint` 는 선택 |

- `hint` 는 새 목표(visit·value·place)에 필수입니다.
- `tol`(허용 오차, 기본 0): 목표값이 무리수일 때만(`"is": "sqrt(3)", "tol": "1/8"`). 형식 검사가 **오차 안에 드는 자리가 정확히 places 곳**인지 봅니다(여럿이면 더듬어 맞히기). 유리수 목표는 분수로 정확히 견줍니다.
- 형식 오류: 끌기·슬라이더로 닿을 수 없는 목표·가 볼 곳, **처음 자리가 이미 목표**(한 번 만지면 끝나는 탐색으로 되돌아감), 목표가 바라보는 상태가 2000개 넘음.

```json
"sliders": [{ "id": "c", "min": -2, "max": 7, "step": 1, "value": 0, "label": "$c$" }],
"objects": [
  { "id": "f", "curve": "x**2-4*x+c", "label": "$y=x^2-4x+c$" },
  { "readout": "roots(f)", "label": "만나는 점" }
],
"goal": { "value": { "of": "roots(f)", "is": 1 }, "hint": "곡선이 가로축에 닿기만 하는 $c$ 를 찾아요." },
"done": "$c=4$ 에서 근이 하나로 겹쳐요."
```

**task** (plot·connect·line·sketch 는 필수, ‘확인하기’로 채점). 목표값은 `{value, check}` 쌍: `value` 는 앱이 쓰는 값, `check` 는 그 값을 문제 조건으로 계산하는 sympy 식(답을 그대로 적으면 오류).

| task | 모드 | 채점 |
|---|---|---|
| `{point:{x:T, y:T}}` | plot | 하나만 찍었고 칸 번호가 같음(정수 비교) |
| `{pointsOn:{curve, count}}` | plot·connect | 모든 점이 곡선 위(상대오차 1e-9), x 중복 없음, count 개 이상 |
| `{line:{slope?:T, through?:{x:T,y:T}, intercept?:T}}` | line | 두 손잡이 칸 번호×칸 간격으로 기울기를 분수로 정확히 비교. 칸 간격이 유리수여야 함 |
| `{line:{tangent:{curve, at}}}` | line | 기울기·접점을 앱이 곡선에서 계산(다항·유리식만). 다른 조건과 같이 못 씀 |
| `{sketch:{curve, tol}}` | sketch | x 표본 21곳 중 80% 이상을 덮고, 덮은 곳의 85% 이상이 `tol` 안. `tol` ≤ 칸 간격. 탭 대체 예외 |

찍기·그리기 모드(plot·connect·line)는 x·y 칸이 각각 **12칸 이하**여야 합니다(가장 좁은 화면에서 한 칸이 손가락으로 고를 만큼). 과제 곡선에는 슬라이더 변수를 쓸 수 없습니다.

**만들어지는 검산 항목**: 구분구적마다 닿는 모든 n 의 큰 어림·작은 어림(`조각 R 큰 어림 n=5` — 앱의 분수 = sympy `summation`)과 넓이(`조각 R 넓이` — 앱이 다항식 부정적분으로 낸 분수 = sympy `integrate`). 곡선마다 parity(TS 계산 vs sympy, 표본 9점), 접선·할선 극한·deriv 에 쓰이는 곡선의 미분 parity, 목표값 answer+check, 점 목표의 칸 번호(= check/칸 간격), 접선 기울기(`diff(곡선,x).subs(x,at)`)·접점(`곡선.subs(x,at)`), ‘풀 수 있나’(plot: 범위 안 격자로 답이 나오나). 새 목표는 ‘목표 판정’(kind `goal`): 목표가 바라보는 끄는 점·슬라이더가 **닿는 모든 상태**에서 앱이 '닿았다'고 본 상태가 sympy 판정과 같은지(실근 개수는 sympy `solveset` 으로 따로 셈), 점 자리 목표는 `목표 점 x·y`(answer+check)도.

**손 조작**: 손잡이 56px(보이는 점 20px), 겹치면 가장 가까운 것. 키보드 방향키(곡선 위 점은 끄는 간격 한 칸), 찍은 점은 Delete 로 지움. 탭 대체: 곡선 위 끄는 점은 ‘◯ 왼쪽으로/오른쪽으로’, plot·connect 는 ‘점 더하기’, line 은 빈 칸을 누르면 가까운 손잡이가 그 칸으로.

**split** (곱셈·분배법칙·곱셈공식): 칸을 눌러 넓이를 열고, 다 열면 `처음 곱 = 칸 넓이 합`.

```json
{ "mode": "split", "w": ["10", "3"], "h": ["10", "2"], "intro": "...", "done": "..." }
```
`w`·`h` 는 항 1~3개(식, x 가능). 검산: 칸 넓이 합 = 처음 곱(숫자면 fraction, x 가 있으면 `expand`).

**grow** (곱의 미분): 가로 w(x)·세로 h(x) 직사각형의 모서리 손잡이로 Δx 를 바꿉니다. 띠 2개·모서리와 ‘띠 두 개 ÷ Δx’, ‘모서리 ÷ Δx’가 보입니다.

```json
{ "mode": "grow", "w": "x**2", "h": "x**3", "wLabel": "$f(x)=x^2$", "hLabel": "$g(x)=x^3$",
  "at": 1, "max": "1/2", "step": "1/20", "goal": "1/20", "intro": "...", "done": "..." }
```
`at`·`max`·`step`·`goal` 은 유리수, `max` 는 `step` 의 정수배(50 이하). Δx 범위에서 가로·세로가 양수로 늘어나야 합니다. 목표: Δx ≤ `goal`(기본 한 칸). 검산: 가로·세로·`diff(w*h)` parity, `(wh)′(at)` 를 sympy diff 와 대조.

**tiles** (인수분해): x²·x·1 타일을 끌어(또는 고르고 판을 눌러) 빈틈없는 직사각형을 만들면 가로·세로가 인수로 보입니다. x 타일은 ‘돌리기’.

```json
{ "mode": "tiles", "tiles": { "x2": 1, "x": 5, "one": 6 }, "factor": "(x+2)*(x+3)", "done": "..." }
```
타일로 직사각형을 만들 수 없으면 형식 오류. 검산: `factor` 를 전개하면 타일 식과 같은가.

## balance — 저울

접시 위 물건(컵·동전)을 **손으로 끌어 바닥에 내리고 다시 올리는** 저울입니다. 버튼이 결과를 대신 그려 주지 않고, 저울은 실제 무게(컵 하나 = 방정식의 해)로 기웁니다. 식은 `a·x + b = c`(왼쪽 컵 a개와 동전 b, 오른쪽 동전 c).

| 칸 | 필수 | 뜻 |
|---|---|---|
| `unit` | ○ | 접시 아래 합계에 붙는 단위(`"원"`, `"개"`). 비워도 됨(`""`) |
| `left` | ○ | `{ "x": 3, "c": 1000 }` 컵 수(1~4 — 가장 좁은 화면의 접시 한 줄)와 왼쪽 동전 합 |
| `right` | ○ | `{ "c": 13000 }` 오른쪽 동전 합 |
| `intro` | ○ | 처음 안내 |
| `ops` | ○ | 단원 글이 짚어 줄 조작 1~6개(아래). **버튼이 아닙니다** |

**손 조작**
- 동전 하나의 값은 `left.c`·`right.c`·덜기 값·해의 최대공약수입니다(13,000원이면 1,000원 동전 13개). 접시 하나에 동전은 왼쪽 8개·오른쪽 16개까지(줄마다 고르게, 한 줄 7개), 해는 자연수여야 합니다.
- 동전은 낱개로 내리고 올립니다. **한쪽만 내린 상태는 실수가 아니라 과정**이라 저울이 기운 채 그대로 있고(틀린 시도로 세지 않음), 반대쪽에도 같은 일을 하면 다시 수평이 됩니다.
- 컵(x)은 무게를 모르는 물건이라 낱개로는 못 내립니다. 왼쪽에 컵만 남고 수평이면 양쪽이 **컵 수만큼의 같은 묶음**으로 나뉘고(오른쪽 12,000원 → 4,000원 묶음 셋, 동전 하나짜리도 묶음 모양), 그때부터 컵 하나·묶음 하나씩 내리고 올립니다. 컵 하나는 늘 남습니다. 학습자가 끈 바로 그 물건이 옮겨지고, 묶이거나 풀릴 때 동전은 제자리에서 묶음 자리로 옮겨 갑니다.
- 화면 글은 x 를 담는 그릇을 'x'로, 동전은 단위가 `원` 이면 '동전' 아니면 '추'라고 부릅니다(단원마다 커피·공책·구슬이라).
- 접시 상자 밖에 놓으면 내려가고, 바닥 물건은 같은 쪽 접시 위에 놓으면 올라갑니다. 옮기려다 아무 일도 안 일어난 끌기·누르기가 2번이면 '눌러서 옮기기'가 켜집니다. 틀린 시도로 세는 것은 실제로 끌었는데 아무 일도 안 일어난 끌기뿐입니다. 키보드: 아래 방향키 = 내리기, 위 = 올리기, Enter·Space(화면 낭독기의 누르기 포함) = 반대쪽으로. 동시에 끄는 물건은 1개.
- 목표: 왼쪽에 컵 하나만 남고 수평(`x = 해`).

**ops** — 기준은 *지금까지 지나온 수평 상태 중 어느 하나*에서 그 조작을 한 결과에 학습자가 닿았는가입니다(한 개씩 번갈아 옮기면 중간 수평을 거치기 쉬워서).
- `{ "op": "sub", "value": 1000, "side": "both", "say": "…" }` 양쪽에서 덜기. 닿으면 `say`.
- `{ "op": "div", "value": 3, "side": "both", "say": "…" }` 양쪽을 나눠 한 묶음만 남기기. `value` 는 컵 수(`left.x`)와 같아야 합니다.
- 형식 검사가 양쪽 조작마다 "한 개씩 번갈아 옮기는 길에서도 이 글이 뜨는가"를 확인합니다.
- `side` 가 `left`·`right` 면 한쪽만 한 상태(기운 상태)에 닿았을 때 `say`, 그 뒤 하나씩 도로 올려 그 조작을 시작한 수평으로 돌아오면 `undo`(필수, 한 번만). 예전처럼 저절로 되돌리지 않습니다. 형식 검사가 "undo 가 보일 길이 있는가"를 확인합니다.
- `add`·`mul` 은 없습니다(저울 밖에서 물건을 가져와야 해서). 짚지 않은 상태에서는 부품이 '수평이에요 / 왼쪽이 더 무거워 내려갔어요'를 보입니다.
- 글의 `{{a}}`(컵 수) `{{b}}`(왼쪽 동전 합) `{{c}}`(오른쪽 동전 합, 쉼표) `{{x}}`(c 그대로)는 그때 저울 값입니다.

```json
{ "type": "balance", "params": {
  "unit": "원", "left": { "x": 3, "c": 1000 }, "right": { "c": 13000 },
  "intro": "쿠키 값부터 덜어 내 볼까요?",
  "ops": [
    { "op": "sub", "value": 1000, "side": "both", "say": "수평 그대로예요. 커피 {{a}}잔 = {{c}}원." },
    { "op": "div", "value": 3, "side": "both", "say": "$x = {{x}}$ 을 찾았어요!" },
    { "op": "sub", "value": 1000, "side": "left", "say": "기울었어요! 오른쪽에서도 똑같이 덜어 보세요.", "undo": "다시 수평이에요." }
  ]
}, "eq": "coffee" }
```

**만들어지는 검산 항목**: 끌기로 닿는 **모든 상태**(개수가 같으면 하나. 동전 한도 안이면 많아야 173개). 수평 상태는 처음 식과 해가 같은가(`equiv`), 기운 상태는 컵에 해를 넣어 어느 쪽이 무거운가(`sign(왼쪽−오른쪽)` 을 sympy 가 다시 계산 — 화면은 이 부호로 기움), 그리고 목표 해. 기우는 각도(차이가 클수록 3°~12°)는 그림이라 검산하지 않습니다.

## 공통

- 레슨에 `equations` 가 있고 부품이 방정식을 그리면(`table`·`balance`·`termDrag`) `eq` 가 필수입니다. 일부러 다른 식이면 `"eq": false`.
- 끄는 동안 ‘계속하기’가 잠깁니다. 동작 줄이기면 움직임이 꺼집니다.
- 펜·손가락·마우스 모두 끌 수 있습니다(Pointer Events). 좌표평면·넓이 모형의 손잡이는 HTML 요소(Handle.tsx), 부품 6종은 SVG 손잡이(SvgHandle.tsx)이고, 끄는 터치는 스크롤을 막습니다(Chrome 은 SVG 안쪽의 `touch-action` 을 무시해서).

---

레슨 장면의 `widget: { "type": "...", "params": { ... } }` 에 넣는 부품의 매개변수와 예시입니다.
이 문서는 수직선·분수 조각·단위원·도형판·경우의 수·확률 실험 6종을 다룹니다(저울·좌표평면·넓이 모형은 이 문서 위쪽, 항 끌기·표는 각 부품 파일의 머리 주석을 보세요).

## 공통 규칙

- **모르는 칸은 오류**입니다. 칸 이름을 틀리면 `npm run verify` 의 형식 검사에서 바로 잡힙니다.
- 화면에 보이는 값(조각 수, 평균, sin 값, 넓이, 경우의 수, 이론 확률)은 **부품 모델이 계산**하고, 검사기가 같은 모델의 결과를 sympy 로 다시 계산해 대조합니다. 작성자가 따로 적을 값은 과제의 답과 그 답의 검산식(`check`)뿐입니다. 검산식에 답을 숫자 그대로 적으면(`"2"`, `"Rational(3,2)"`) 거부됩니다.
- 끄는 것에는 늘 **누르는 대체 버튼**이 함께 나옵니다(한 칸 이동, 보내기 등). 끄는 동안에는 하단 '계속하기'가 잠깁니다.
- 부품은 목표를 이루면 장면에 "끝"을 알립니다. 목표를 이루지 않아도 "계속하기"로 넘어갈 수 있습니다(`gate` 는 진행을 막지 않음). 과제가 없는 부품은 한 번 만져 보면 끝으로 봅니다 — 그래서 탐색 장면에는 되도록 목표(좌표평면·도형판 `goal`)를 둡니다.
- **결론 글 공개**: 탐색 장면에 `"afterGoal": true` 를 두면 카드 아래 글(`after`)이 목표를 이룬 뒤에 보입니다(결론을 먼저 읽고 조작하지 않게). 목표를 못 이루고 '계속하기'로 넘어가도 그 장면을 떠나면(다음 장면이 열리면) 보입니다 — 장면 완료로 적지는 않습니다. 목표가 있는 부품(좌표평면 `goal`·`task`, 도형판 `goal`·`cut`)에만 쓸 수 있습니다.
- 글자를 넣는 칸(점 이름, 안내 등)은 짧게 씁니다. 수식은 `$…$`.

## numberLine — 수직선

| 칸 | 필수 | 뜻 |
|---|---|---|
| `min`, `max` | ○ | 정수. 양 끝 값 |
| `step` | ○ | 칸 간격(`"1"`, `"1/2"`, `"1/4"`). 범위를 나누어떨어지게 해야 하고 60칸까지 |
| `label` | | 숫자를 적는 간격(`step` 의 배수). 없으면 1 |
| `points` | | `[{ id: "P", at: "0", drag: true, label?: "P" }]` 최대 4개. id 는 대문자 한 글자, `at` 은 칸 위의 값 |
| `jumps` | | `{ start: "5", moves: ["-7", "3"] }` 점프 화살표(덧셈·뺄셈). '다음 이동 보기'로 하나씩 펼친다. 모두 펼치면 끝 |
| `region` | | 보여 주기만 하는 구간 `{ lo?: { at, open }, hi?: { at, open } }`. `open: true` 면 빈 점 |
| `data` | | `{ values: ["2","3","3","4","10"], show: ["mean","median"], drag?: true, digits?: 1 }` 자료 점과 평균·중앙값 선. `drag` 면 점을 끌어 평균이 움직이는 걸 본다 |
| `task` | | 아래 둘 중 하나. '확인' 버튼으로 채점 |

과제:
- 점 찍기 `{ "type": "point", "point": "P", "answer": "3/2", "check": "Rational(1,2)+1" }` — 끄는 점 P 를 답 칸에 놓기.
- 구간 고르기 `{ "type": "interval", "ineq": "2*x+1<7", "answer": { "at": "3", "dir": "left", "open": true } }` — 끝점을 끌고 '빈 점/찬 점', '왼쪽/오른쪽'을 골라 부등식의 해를 나타내기. 검산은 sympy `solveset` 의 해와 정답 구간이 같은지, 빈 점·찬 점을 바꾼 구간은 다른지 봅니다.

```json
{ "type": "numberLine", "params": {
  "min": -5, "max": 5, "step": "1",
  "task": { "type": "interval", "ineq": "2*x+1<7", "answer": { "at": "3", "dir": "left", "open": true } }
} }
```

## fraction — 분수 조각

| 칸 | 필수 | 뜻 |
|---|---|---|
| `shape` | ○ | `bar`(막대) · `circle`(원) |
| `mode` | ○ | `compare` · `add` · `sub` · `mul` · `div` |
| `a`, `b` | ○ | 기약분수(`"1/2"`). 분모 12 이하, 그림이 2칸(값 2)을 넘지 않게 |
| `cut` | | 다시 자르기 슬라이더 `{ min: 2, max: 12 }`(한 칸을 몇 조각으로). 최대 24 |
| `still` | | `true` 면 그림만(질문 장면의 도입 그림). `cut` 과 함께 쓸 수 없고 검산 항목도 없음 |

모드별 동작과 목표:
- `add`·`sub`: 아래 막대를 위로 끌어 놓으면(또는 '위로 보내기') 합치기·덜어 내기. **두 분수가 같은 크기 조각일 때만** 들어갑니다. 자르는 수가 두 분모의 공배수여야 하므로, `cut` 범위 안에 공통분모가 없으면 형식 오류입니다. 목표 = 합치기. 화면 식은 `3/6 + 2/6 = 5/6` 처럼 바뀌고, 최소공배수보다 큰 수로 잘랐으면 "더 작은 수로도 돼요"를 덧붙입니다. 검산: 결과값, 가장 작은 공통분모(`ilcm`), 범위 안 모든 공통분모에서의 조각 수.
- `compare`: '위가 더 커요 / 같아요 / 아래가 더 커요'. 목표 = 맞히기. 검산: `sign(a-b)`.
- `mul`: 넓이 모형. 가로 손잡이로 `a`, 세로 손잡이로 `b` 만큼 칠하면 겹친 칸이 곱. `a`·`b` 는 1 이하. 검산: 곱과 겹친 칸 수.
- `div`: `b` 조각을 `a` 위에 몇 번 놓는지. 목표 = 다 덮기. 검산: 몫과 놓는 횟수(`ceiling`).

```json
{ "type": "fraction", "params": { "shape": "bar", "mode": "add", "a": "1/2", "b": "1/3", "cut": { "min": 2, "max": 12 } } }
```

## unitCircle — 단위원

| 칸 | 필수 | 뜻 |
|---|---|---|
| `unit` | ○ | `deg`(θ = 30°) · `rad`(θ = π/6 (30°)) |
| `start` | ○ | 처음 각도(도) |
| `snap` | ○ | `"special"`(30°·45°의 배수 16개) 또는 360 을 나누는 간격(5 이상, 예: 15) |
| `show` | ○ | `["sin","cos","tan"]` 중 보일 값 |
| `unroll` | | `true` 면 오른쪽에 사인 그래프를 펼쳐 그림(점의 높이가 그래프로 이어진다) |
| `task` | | `{ "answer": 150, "check": "deg(pi - asin(Rational(1,2)))" }` 각도 맞히기('확인'). 답은 스냅으로 닿는 각도 |

특수각은 √ 가 든 정확한 값, 나머지는 소수 셋째 자리 근삿값(≈)을 보입니다. tan 이 정의되지 않으면 "정할 수 없어요". 검산은 닿을 수 있는 **모든 각도**의 값을 sympy `sin(rad(θ))` 등과 대조합니다.

```json
{ "type": "unitCircle", "params": { "unit": "rad", "start": 30, "snap": "special", "show": ["sin", "cos"], "unroll": true } }
```

## shape — 도형판

| 칸 | 필수 | 뜻 |
|---|---|---|
| `grid` | ○ | `{ w, h }` 격자 크기(가로·세로 16까지). y 는 위로 |
| `points` | ○ | `{ id: "A", x, y, drag?: true, on?: …, range?: … }` 또는 계산되는 점(`foot`·`follow`·`mirror`, 아래) 최대 20개. id 는 대문자 한 글자, 뒤에 ′ 하나까지(`F′`). `pieces` 가 있으면 빈 목록도 됨 |
| `polygons` | | `[["A","B","C"]]` 다각형(점 id 목록) |
| `circles` | | `[{ c: "O", r: 3 }]` — r 은 0.5 단위(2.5), 또는 `{ c: "O", through: "A" }`(A 까지 거리 — A 가 끄는 점이면 컴퍼스처럼 늘고 줆. 닿는 어느 자리에서든 원이 격자 안이어야 함 — 아니면 형식 오류, `range` 를 좁히세요) |
| `segments` | | `[["P","Q"]]` 최대 12개. 객체로 `{ seg: ["P","Q"], dash?: true, extend?: true }` — 점선(숨은 선·보조선), 연장선(격자 끝까지 늘인 직선) |
| `curves` | | `[{ ellipse: { c: "O", a: 5, b: 3 } }]`·`[{ hyperbola: { c, a, b } }]`(가로로 벌어진 두 갈래). 그 위 점은 `on: { curve: 번호 }`(아래) |
| `arcs` | | `[{ c: "O", from: "A", to: "B" }]` 원 위 호 강조(중심 c, 반지름 cA, A 에서 B 까지 시계 반대 방향) |
| `unit` | | `mm`·`cm`·`m`·`km` — 길이 `5 m`, 넓이·제곱 `12 m²` |
| `pieces` · `outline` | | 조각 여러 개 끌어 옮기기·돌리기(아래) |
| `measures` | | 최대 8개. `{ len: ["A","B"] }` · `{ angle: ["B","A","C"] }`(가운데가 꼭짓점) · `{ area: 0 }`(다각형 번호) · 묶은 값 `{ sum: [0, 1] }`·`{ diff: [0, 1] }`·`{ ratio: [0, 1] }`(아래) |
| `digits` | | 반올림 자리(기본 1). 정확히 떨어지면 `=`, 아니면 `≈` |
| `cut` | | 잘라 옮기기(아래) |
| `note` | | 그림 위 안내 한 줄 |
| `goal` | | 목표(아래). `cut` 과 함께 쓸 수 없음 |
| `done` | | 목표를 이뤘을 때 글(`goal` 이 있을 때만) |

점 제약:
- 자유 점: 격자점에 붙고 격자 밖으로 못 나감.
- `on: { seg: ["P","Q"] }`: 선분 PQ 위의 격자점으로만(끝점 P·Q 는 고정 점, 사이에 격자점이 있어야 함).
- `on: { circle: ["O", 3] }` + `deg: 90`: 중심 O, 반지름 3 인 원 위에서 15° 간격으로(x·y 대신 `deg`).
- `aux: true`(보조점): 점·이름표를 그리지 않는 고정 점. 선분 위 점의 끝(`seg`)·`segments` 끝·수선의 발 직선으로만 쓰고, 다각형·측정·원에는 못 씀(보이지 않는 점을 읽게 되므로).
- `foot: { from: "P", line: ["L","R"] }`(수선의 발): 점 P 에서 직선 LR 에 내린 발. 자리를 적지 않고 늘 계산해 **P 를 끄는 동안 따라 움직입니다**(끄는 점이 아님). `from`·`line` 은 앞에 적은 점, 직선의 두 점은 서로 다른 자리의 고정 격자점(보조점 가능 — 축·준선을 보조점 둘로), 발에서 다시 발을 내리거나 발을 선분·원 제약의 끝·중심으로 쓰면 형식 오류. 발은 격자점이 아닐 수 있어 그 자리의 측정값은 수로 견주고 sympy 가 `Line(L, R).projection(P)` 로 정확히 다시 판정합니다. 직선 LR 은 **그려야 하고**(`segments` 의 선분이나 다각형의 변), P 가 닿는 모든 자리에서 발이 그 선분 안에 놓여야 합니다(목표가 없어도 형식 검사가 늘어놓아 확인 — 아니면 발이 그린 선 밖·그림 밖에 뜸). 축·준선은 끝점을 격자 가장자리에 두세요.
- 선분·원 위 끄는 점은 점마다 ◀▶ 버튼이 있고, 자유 점은 고른 점의 화살표 버튼으로 옮깁니다. 키·버튼은 마지막 입력 뒤 0.6초 멈추거나 포커스가 떠날 때 한 번 목표를 판정합니다.

목표 `goal`(좌표평면과 같은 규칙 — 손을 뗀 자리만 판정, 8번 떼도 못 이루면 `hint`, 진행을 막지 않음). `of` 는 `measures` 의 번호(화면에 보이는 측정값만 목표로):
- 값 맞추기 `{"value": {"of": 1, "is": 20}, "hint": "윗변을 2 로"}` — "넓이를 20으로". `places` 로 여러 자리.
- 여러 곳 가 보기 `{"visit": {"of": 0, "at": [60, 90, 120]}, "hint": "…"}` — "60°·90°·120° 모두 보기".
- 다른 측정값과 견주기 `{"value": {"of": 0, "is": {"of": 1}, "places": 3}, "hint": "…"}` — "PF = PH 인 곳 세 곳". `is` 에 수 대신 `{ "of": 측정 번호 }`. 같은 종류끼리만(길이↔길이, 각↔각, 비↔비), 자기 자신이나 내용이 같은 측정값(PF 와 FP, ∠FPG 와 ∠GPF)과는 못 견줌. 두 값 모두 정확히 계산하므로 `tol` 을 두면 형식 오류. 두 측정값이 화면에 같은 수로 보이는데(PA ≈ 9, PB ≈ 9) 목표가 아닌 자리가 있으면 형식 오류 — `digits` 를 늘리세요. 두 측정값을 바꾸는 끄는 점을 모두 바라봅니다.
- 처음 자리가 이미 목표면, 끄는 점으로 닿을 수 없으면, 그 측정값을 바꾸는 끄는 점이 없으면 형식 오류. 무리수 목표는 `tol`(좌표평면과 같음). 검산은 끄는 점이 닿는 모든 자리를 sympy 가 다시 판정(‘목표 판정’).

묶은 측정값(요청 106 — 이차곡선 정의·닮음비): 앞에 적은 **길이·각** 측정값의 번호로 만듭니다(묶은 값·넓이는 다시 묶지 않음, 길이와 각은 섞지 않음, 같은 측정값을 두 번 묶지 않음). 측정 하나에 열쇠(`len`·`angle`·`area`·`sum`·`diff`·`ratio`)는 하나만.
- `{ "sum": [0, 1] }` → `PF + PG = 10`(항 2~4개 — `∠CAB + ∠ABC + ∠BCA = 180°` 도 됨)
- `{ "diff": [0, 1] }` → `|PF − PG| = 6`(차의 크기, 항 2개)
- `{ "ratio": [0, 1] }` → `AD ÷ AB = 0.25`(길이끼리만, 분모가 0 이면 "정할 수 없어요")
- 앱은 항이 모두 분수로 정확할 때만 분수로, 아니면 수로 견주고(합이 정수여도 항이 무리수면), sympy 가 `(PF) + (PG)`·`Abs((PF) - (PG))`·`(AD)/(AB)` 로 정확히 다시 판정합니다.

```json
{ "type": "shape", "params": {
  "grid": { "w": 10, "h": 8 },
  "points": [
    { "id": "F", "x": 5, "y": 4 },
    { "id": "L", "x": 0, "y": 2, "aux": true }, { "id": "R", "x": 10, "y": 2, "aux": true },
    { "id": "P", "x": 5, "y": 6, "drag": true },
    { "id": "H", "foot": { "from": "P", "line": ["L", "R"] } }
  ],
  "segments": [["L", "R"], ["P", "F"], ["P", "H"]],
  "measures": [{ "len": ["P", "F"] }, { "len": ["P", "H"] }],
  "goal": { "value": { "of": 0, "is": { "of": 1 }, "places": 3 }, "hint": "준선까지의 거리와 비교해 보세요" },
  "done": "PF 와 PH 가 같은 곳을 세 곳 찾았어요."
} }
```

타원(합): `"measures": [{ "len": ["P","F"] }, { "len": ["P","G"] }, { "sum": [0, 1] }]`, `"goal": { "value": { "of": 2, "is": 10, "places": 3 }, "hint": "…" }`. 닮음(비끼리): `"measures": [{ "len": ["A","D"] }, { "len": ["A","B"] }, { "len": ["A","E"] }, { "len": ["A","C"] }, { "ratio": [0, 1] }, { "ratio": [2, 3] }]`, `"goal": { "value": { "of": 4, "is": { "of": 5 }, "places": 2 }, "hint": "…" }`.

잘라 옮기기 `cut: { piece: [...], rest: [...], by: [dx, dy], result: [[x,y], …] }`: `polygons[0]` 을 `piece`(옮길 조각)와 `rest` 로 나누고, 조각을 `by` 만큼 끌어 옮기면(또는 '조각 옮기기') `result` 모양이 됩니다. 조각+나머지의 넓이와 `result` 의 넓이가 처음 넓이와 다르면 형식 오류. 검산은 넓이 셋(처음·조각+나머지·옮긴 모양)을 sympy 로 대조합니다. 잘라 옮기기에는 끄는 점을 두지 않습니다.

```json
{ "type": "shape", "params": {
  "grid": { "w": 8, "h": 4 },
  "points": [ { "id": "A", "x": 0, "y": 0 }, { "id": "B", "x": 4, "y": 0 }, { "id": "C", "x": 6, "y": 3 }, { "id": "D", "x": 2, "y": 3 }, { "id": "E", "x": 2, "y": 0 } ],
  "polygons": [["A", "B", "C", "D"]],
  "cut": { "piece": ["A", "E", "D"], "rest": ["E", "B", "C", "D"], "by": [4, 0], "result": [[2, 0], [6, 0], [6, 3], [2, 3]] },
  "note": "왼쪽 세모 조각을 오른쪽 끝으로 옮겨 보세요."
} }
```

### 3-다 추가 옵션

끄는 범위 `range: { x: [lo, hi], y: [lo, hi] }`(끄는 자유 점만, 없는 축은 격자 전체, 한 축만 막으면 가로·세로로만): 끄는 점이 셋 이상이어도 목표 판정 자리(상한 2000)에 들게(요청 133). 처음 자리는 범위 안.

계산되는 점(자리를 적지 않고 앞에 적은 점으로 늘 계산 — 끄는 점이 아님):
- 따라오는 점 `{ id: "B", y: 0, follow: { x: "C" } }`: x 를 C 의 x 로 받는다(받지 않는 칸만 적음). 직사각형 한 꼭짓점 C 를 끌면 B·D 가 따라와 **모양이 유지**된다.
- 마주 보는 점 `{ id: "R", mirror: { of: "P", about: "O" } }`(점대칭) · `{ id: "F′", mirror: { of: "F", across: ["L","M"] } }`(선대칭, 축은 고정 격자점 둘). 기대는 끄는 점이 닿는 어느 자리에서든 격자 안이어야 한다(아니면 형식 오류 — `range` 를 좁히세요).

```json
{ "grid": { "w": 12, "h": 8 },
  "points": [ { "id": "A", "x": 0, "y": 0 },
    { "id": "C", "x": 4, "y": 2, "drag": true, "range": { "x": [1, 12], "y": [1, 8] } },
    { "id": "B", "y": 0, "follow": { "x": "C" } }, { "id": "D", "x": 0, "follow": { "y": "C" } } ],
  "polygons": [["A","B","C","D"]],
  "measures": [ { "len": ["A","B"], "label": "가로", "tag": true }, { "len": ["B","C"], "label": "세로", "tag": true }, { "area": 0, "tag": true } ],
  "unit": "m", "digits": 0,
  "goal": { "value": { "of": 2, "is": 12, "places": 4 }, "hint": "가로 × 세로 = 12" } }
```

원·곡선 위 점:
- `on: { circle: ["O", 2.5] }`(0.5 단위) · `on: { circle: ["O", "A"] }`(고정 점 A 까지 거리 — √2 를 컴퍼스로 옮기기).
- `on: { curve: 0 }` + `deg`: 곡선 위 15° 간격 매개변수(타원 (a cos t, b sin t), 쌍곡선 (a / cos t, b tan t)). 격자 밖·무한히 먼 자리(쌍곡선 90°·270°)는 건너뛴다. 끄는 점인데 닿는 자리가 하나뿐이면 형식 오류(끌어도 그대로). 격자점이 아니라 sympy 가 같은 매개변수로 다시 계산한다. 타원 위 PF + PG, 쌍곡선 위 |PF − PG| 가 어디서나 2a.

측정값 더하기(측정값 객체에 같이 적음):
- `label: "가로"`(8자까지) 이름 대신 · `tag: true` 그림 위에 값(길이는 변 바깥, 넓이는 가운데, 각은 꼭짓점 안, 호는 호 바깥 — 길이·넓이·각·호만).
- 각 `mark: true`(각 호, 직각이면 네모) · `ccw: true`(A 에서 C 로 시계 반대 방향 0°~360° — 오목각 270°. 차례가 뜻이라 ∠ABC 와 ∠CBA 는 다른 값).
- `{ arc: 0 }` 호 길이(arcs 번호) · `{ around: 0 }` 원주(circles 번호).
- 계산값 `{ sq: 0 }` → `AB²`(길이만, 넓이와 같은 종류라 `AB² + BC²` 와 `CA²` 를 견줄 수 있음) · `{ sin: 1 }` → `sin A`(각만) · 비의 분모에 sin: `{ ratio: [0, 2] }` → `BC ÷ sin A`(사인법칙).

조각 여러 개 `pieces: [{ at: [[x,y],…], to: [[x,y],…] }]`(최대 6개) + 빈 틀 `outline: [[x,y],…]`(점선, 선택): 조각을 끌면 격자 칸 단위로 옮긴다. 고르지 않은 조각을 **톡 누르면 고르고, 고른 조각을 한 번 더 톡 누르면 90° 돌린다**(처음 자리 가운데 격자점 둘레 — 꼭짓점이 늘 격자점이라 넓이가 정확히 그대로. 격자 가장자리에서는 안으로 밀려 네 번 돌려도 제자리가 아닐 수 있음). 톡은 끄는 동안 가장 멀리 간 거리가 8px 미만일 때. 고른 조각은 화살표·⟲ 버튼, 키보드 방향키·Enter/Space/R. 판정은 손을 뗄 때(키·버튼은 멈춘 뒤 한 번) — 끄는 동안은 맞은 자리에 와도 초록이 되지 않는다. 모든 조각이 목표 자리(둘레를 도는 꼭짓점 차례로 비교 — 돌려도 같은 모양·같은 모양 조각끼리 바꿔 놓기도 맞음, 거울상은 다름)를 하나씩 채우면 끝(`done` 글, 한 번 이루면 조각을 빼도 유지). 같은 모양 조각 둘을 한 자리에 겹치면 한 곳만 채운 것. `to` 가 `at` 을 돌리고 옮겨 닿지 않는 자리(뒤집어야 함)면, 목표 자리끼리 같거나 겹치면, 목표 자리가 빈 틀 밖이면, 빈 틀 넓이가 조각 넓이 합과 다르면, 처음 자리가 이미 목표면 형식 오류. `cut`·`goal`·끄는 점과 함께 쓸 수 없음. 검산은 sympy `rotate` 로 돌려 옮긴 자리 = 앱의 목표 자리, 그 넓이 = 처음 넓이, 조각 합 = 틀 넓이.

```json
{ "grid": { "w": 8, "h": 8 }, "points": [],
  "pieces": [ { "at": [[0,0],[2,0],[0,2]], "to": [[4,2],[6,2],[4,4]] },
              { "at": [[0,5],[2,5],[0,7]], "to": [[6,2],[6,4],[4,4]] } ],
  "outline": [[4,2],[6,2],[6,4],[4,4]],
  "done": "두 조각으로 정사각형을 채웠어요." }
```

## count — 경우의 수

`mode` 에 따라 칸과 조작이 다릅니다. 움직임이 곧 수학인 셋은 손으로 옮깁니다(2026-11-23 결정 D1, 원칙 P1). 나머지는 누르기 그대로입니다. 부품 문구는 중립어('자리'·'경우'·'짝')이고, 장면 글에 맞추려면 `words` 칸으로 바꿉니다(아래).

| mode | 칸 | 조작 · 끝 |
|---|---|---|
| `list` | `items`(2~6), `k`, `words?` | **줄 세우기**: 위 '남은 것' 칸의 칩을 아래 자리(첫째·둘째…)로 끌어 세운다. 자리끼리 끌면 두 자리가 맞바뀌고, 남은 것에서 찬 자리로 들어오면 원래 있던 칩은 위로. 자리가 다 차면 그 순서가 한 경우로 적히고, 이미 있는 경우면 적지 않고 목록의 그 경우가 깜빡인다(틀린 시도로 세지 않음 — 자리를 바꾸다 지나가는 과정이라). 모두 찾으면 끝 — 목록이 첫째 자리 물건별 묶음으로 정리되고 읽는 값 줄에 결론 "첫째 4 × 둘째 3 = 12가지" |
| `pick` (k=2) | `items`(2~6), `k`, `words?` | **선 잇기**: 정다각형 꼭짓점의 하나에서 다른 하나까지 끌면 선이 그어지고 짝 목록에 쌓인다. 반대 방향으로 다시 그어도 같은 짝이라 막히고 그 선이 깜빡인다. 모두 이으면 끝 — 하나마다 이은 수(n−1)가 뜨고 결론 "하나마다 3개 × 4 = 12, 짝 하나를 양쪽에서 두 번 셌으니 ÷ 2 = 6가지" |
| `pick` (k≠2) | `items`, `k` | 누르기: 물건을 눌러 k개를 고르면 한 경우(고른 순서는 상관없음) |
| `repeat` | `items`, `k`(4까지) | 누르기: 같은 것을 여러 번 고를 수 있는 나열 |
| `tree` | `items`, `k`, `repeat?` | 수형도를 한 단계씩 펼치기(누르기). 끝 가지 수 = 경우의 수 |
| `pascal` | `rows`(1~8) | 맨 아래 줄의 ? 를 눌러 위 두 수의 합으로 채우기 |
| `venn` | `sets: { names: [이름, 이름], a: [...], b: [...], u?: [...] }`, `words?` | **벤 분류**: 아래 더미 맨 위 카드를 끌어 '이름1에만 · 둘 다 · 이름2에만 · 둘 다 아님'에 넣는다. 놓는 순간에는 아무 신호도 없고, 다 넣은 뒤 '확인하기'로만 채점 — 틀린 카드만 빨간 테두리(옮기면 지워지고 남은 틀린 수로 안내가 바뀐다). 다 맞으면 끝 — 영역별 개수와 "둘 중 하나라도: 6 + 4 − 3 = 7개"(초점이 이 줄로 간다) |

- 직접 조작 공통: 판정은 손을 뗀 자리에서만(P3). 끄는 동안은 화면을 다시 그리지 않는다(P8). 동시에 끄는 것은 하나(P9). 판 위를 쓸면 페이지가 스크롤된다(칩·카드·점에서 시작한 터치만 끌기).
- 누르기도 첫 번부터 된다(칩 → 자리, 하나 → 다른 하나, 카드 → 넣을 곳 단추 넷) — 화면 낭독기의 두 번 두드리기가 누르기로 들어오기 때문. 안내 글만 P4 대로: 첫 누르기는 "누른 채 끌어 보세요", 두 번째(또는 두 번째로 놓친 끌기)에 "끌기가 어려우면 눌러도 돼요".
- 줄 세우기·선 잇기에는 '처음부터 다시'가 있다. 다 찾은 뒤에는 안내·틀린 시도 세기를 하지 않는다(결론 줄은 그대로).
- 키보드는 처음부터 된다. 줄: ←/→ 옆 자리와 맞바꾸기, ↓ 빈자리로, ↑ 남은 것으로, Enter 로 골라 다른 칩 자리로. 선: Enter 로 잡고 다른 하나에서 Enter, 방향키로 이웃, Esc 취소(초점은 점선 바깥 고리). 벤: Enter 로 넣을 곳 단추 넷, Esc 닫기. 화면 낭독기는 "B, 둘째 자리", "지금 자리: B, A, 빈자리"처럼 읽는다.
- **`words`(선택) — 장면이 바꾸는 부품 문구**:

| 칸 | 쓰는 곳 | 기본 | 뜻 |
|---|---|---|---|
| `intro` | 셋 다 | 조작 안내 한 줄 | 처음 안내 칸 글 |
| `wait` | `list` | `남은 것` | 아직 세우지 않은 칩이 있는 칸 이름 |
| `seats` | `list` | `첫째`·`둘째`… | 자리 이름 k 개(예: `["회장", "부회장"]`). 결론 글 "회장 4 × 부회장 3 = 12가지"·묶음 머리에도 쓰인다 |
| `item` | `pick`(k=2) | `하나` | 하나를 부르는 말 — "깃발마다 4개 × 5 = 20…" |
| `out` | `venn` | `둘 다 아님` | 두 원 밖 칸 이름 |
| `done` | `list`·`pick`(k=2) | 위 결론 글 | 결론 글 전체. **`{식}` 이 꼭 있어야** 하고 그 자리에 모델이 계산한 식이 들어간다(줄: `3 × 2 × 1 = 6`, 선: `3 × 4 ÷ 2 = 6`) — 숫자를 글에 직접 적지 않게 |

- **전체집합 `u`(선택)**: 있으면 분류할 카드가 `u` 의 원소 전부가 되고('둘 다 아님' 칸에 들어갈 원소가 생김), 그림에 U 가 붙고, 다 맞힌 뒤 이름1의 여집합을 칠해 "이름1의 여집합(칠한 곳): 6 − 3 = 3개"를 보인다. `u` 는 a·b 의 원소를 모두 품어야 한다(최대 16개). 없으면 a∪b 만 분류한다. 카드는 수면 수 차례, 아니면 가나다 차례로 나온다(a 다음 b 차례로 두면 답이 드러나서). 더미로 되돌린 카드는 맨 위로 온다.
- **벤 자리 수**: 카드는 통째로(네 모서리·네 변 가운데까지) 그 칸 안에 서고, 같은 칸 카드는 가운데 줄부터 가운데 정렬로 자동 줄 맞춤한다(빠지면 다시 가운데로 모임). 그래서 칸마다 들어가는 수가 정해져 있다: **겹친 곳 4 · 에만 각 3 · 둘 다 아님 6**. 자리가 다 찬 칸에는 더 넣지 못하고, 정답대로 넣었을 때 한 칸 원소가 자리보다 많으면 형식 오류.
- **글자 폭 형식 검사**: 칩·점·카드는 크기가 정해져 있어 글자가 13px 아래로 줄어야 들어가면 형식 오류(칩 지름 44~56 · 점 54 · 카드 44 — 대략 칩 한글 3자, 점 한글 3자, 카드 숫자 4자까지). 자리 이름·벤 그림 이름(한 줄)·'넣을 곳' 단추(두 줄)·완료 묶음 표 한 칸(물건 n 칸으로 나눈 폭)도 같은 어림으로 막는다. 누르기 화면(셋 이상 고르기 등)은 단추가 글자에 맞춰 늘어 제한 없음.

경우가 24가지를 넘으면 손으로 찾기 어려워 형식 오류입니다. 검산은 모델이 모두 늘어놓아 센 수를 sympy 공식(`ff`, `binomial`, 거듭제곱, `FiniteSet` 의 합·교집합)과 대조합니다. 화면 결론 글의 수도 검산합니다: 선 잇기 `하나마다 짝`(`binomial(n, 2)*2/n`)·`두 번 센 수`(`ff(n, 2)`), 벤 `a에만`(`len(A - B)`)·`b에만`(`len(B - A)`), `u` 가 있으면 `여집합`(`len(U - A)`)·`밖`(`len(U - (A | B))`).

```json
{ "type": "count", "params": { "mode": "list", "items": ["A", "B", "C", "D"], "k": 2, "words": { "seats": ["회장", "부회장"], "wait": "후보" } } }
```

## simulate — 확률 실험

| 칸 | 필수 | 뜻 |
|---|---|---|
| `device` | ○ | `coin` · `die` · `bag` · `trial`(성공 횟수) |
| `n` | trial 은 ○ | 동전 수(1~4, 2개 이상이면 '앞면 수'별) · 주사위 수(1~2, 2개면 '눈의 합'별) · trial 의 시행 수(1~10). 주머니에는 없음 |

**직접 던지기**: '던지기'(주머니는 '꺼내기', trial 은 '해 보기')를 한 번 누르면 한 번, **꾹 누르고 있으면 점점 빠르게 계속**(초당 약 7 → 33 → 83번) 던지고, 떼면 멈춥니다. 키보드는 Space·Enter 한 번 = 한 번(누르고 있으면 계속), 길게 누르기 어려우면 '계속' 단추로 켜고 끕니다('계속'은 `goal` 횟수에 닿으면 한 번 멈춥니다 — 다시 켜면 이어서). 창이 가려지거나 장면이 화면 밖으로 밀려나거나 되감기를 잡으면 멈춥니다. 결과를 대신 그려 주는 '100번' 같은 버튼은 없습니다(P2). 던진 기록은 지우지 않고 남아 **되감기** 손잡이로 앞뒤로 훑습니다(같은 시드·같은 횟수면 같은 기록). 기록은 10000번까지(차면 '기록이 가득 찼어요' — 던지기·계속 단추가 꺼짐).

## factorTree — 소인수분해 나무

**깨닫게 할 것**: 어떻게 쪼개기 시작해도(72 = 2 × 36 이든 8 × 9 든) 끝에 남는 소수 조각은 똑같다 — 소인수분해는 하나뿐.

| 칸 | 필수 | 뜻 |
|---|---|---|
| `n` | ○ | 쪼갤 수(4~999). 아래 조건을 어기면 형식 오류 |

조작: 나무 끝의 수를 누르고 숫자판(2~9)에서 나눌 수를 누르면 (나눈 수, 몫) 두 마디로 갈라집니다. 4·6·8·9 같은 합성수로도 쪼갤 수 있어 나무 모양이 여러 가지가 됩니다. 더 못 쪼갠다 싶으면 '소수예요' — 맞으면 동그라미. 나누어떨어지지 않는 수·소수가 아닌 수는 **누른 뒤에만** 알립니다(숫자판은 나누어떨어지는 수만 켜지 않음, P3). 모든 끝이 소수면 목표를 이룬 것이고, '다른 방법으로 다시 쪼개기'로 두 번째 나무를 만들면 첫 나무와 견준 글("지난번 나무도 2³ × 3² — …")이 나옵니다. 모든 조작이 단추라 Tab·Enter 로 됩니다. 장면 제목이 과제("72를 더 쪼갤 수 없을 때까지 쪼개 보세요")를 맡고, 부품 안에는 따로 적지 않습니다.

조건(형식 검사):
- 소수는 안 됨(쪼갤 것이 없음).
- **소인수 5개까지**(겹치는 것 포함). 나무는 소인수 개수만큼 층이 생겨, 6개(96 = 2⁵ × 3)면 접은 화면 382×580 을 넘칩니다.
- 10 보다 큰 소인수는 하나까지(121 = 11 × 11 은 숫자판으로 못 쪼갬).
- 첫 쪼개기가 두 가지 이상(8 = 2 × 4 처럼 한 가지면 '다른 방법으로'가 뜻이 없음).

검산: 숫자판으로 만들 수 있는 모든 나무의 잎을 늘어놓아 sympy `factorint` 와 같은지(잎 = 소인수분해), 나무에 나올 수 있는 모든 수에서 '소수예요' 판정이 sympy `isprime` 과 같은지.

```json
{ "type": "factorTree", "params": { "n": 72 } }
```

## column — 세로셈 가족

**깨닫게 할 것**: 나눗셈은 자리마다 되풀이하는 같은 일이다 — 그래서 남은 수가 돌아오면 몫이 되풀이되고(순환소수), 조립제법의 마지막 칸은 저절로 f(a) 가 되고, 사다리 왼쪽에 쌓인 수는 두 수가 함께 가진 조각(최대공약수)이다.

한 부품 안의 세 모드입니다(D3 시안 승인 — `outputs/widgets-v2/d3/long-drag.html` · `synth.html` · `ladder.html`). 손으로 하는 일이 곧 그 계산의 뜻입니다(P1).

| mode | 칸 | 조작 · 끝 |
|---|---|---|
| `long` | `dividend`(1~99999), `divisor`(2~99), `decimal?`(기본 false) | **덜어 내기 막대**: 오른쪽 손잡이를 위로 끌면 나누는 수 토막이 하나씩 쌓인다(지금 나누는 수 막대를 넘친 토막은 빗금 — 중립색). 손을 떼면 판정: 넘치면 "뺄 수 없어요", 한 토막 더 들어가면 "한 번 더". 맞으면 몫·곱·남은 수가 적히고, 맨 위 줄의 다음 수(소수면 흐린 0)를 끌어 남은 수 옆 점선 칸에 내린다. 하나도 안 들어가는 자리는 토막을 올려 넘치는 걸 보고 0 으로 내려 놓는다(곱·뺄셈 줄 없이 다음 수를 같은 줄에). 몫 첫 자리가 0 이면(1 ÷ 20 의 10) 다음 0 은 저절로 내려와 바로 100 을 나눈다 — 아직 덜어 낸 것이 없는 줄에 0 을 손으로 옮기는 일은 뜻이 없어서. `decimal` 이면 남은 수가 0 이 되거나, 소수점 뒤에서 이미 나온 남은 수로 돌아와 그 옆에 0 을 내리면 끝(되풀이 마디 위에 점). 아니면 마지막 자리까지 내려 몫·나머지 |
| `synth` | `coeffs`(높은 차수부터 3~5개 = 2~4차, 정수 −99~99, 첫 계수 0 아님), `root`(−9~9, 0 아님 — x − root 로 나눔) | **조립제법**: 첫 계수를 같은 열 맨 아래로 끌어 내린 뒤, 아래 줄 맨 끝 수를 오른쪽 위 칸(가운데 줄)으로 끌어 올린다 — 손가락에 '값 × 근'이 따라가고, 놓으면 곱이 적히고 위 수와 더한 값이 아래로 내려온다. 빈칸은 모두 같은 점선이라 어디에 놓을지는 학생이 정한다. 끝나면 몫·나머지와 "f(2) = 2³ − 2×2 + 1 = 5 — 마지막 칸과 같아요" |
| `ladder` | `numbers`(두 수, 2~999), `cards?`(소수 1~4장, 작은 것부터. 기본 2·3·5·7) | **나눗셈 사다리**: 수 카드를 맨 아래 줄 왼쪽 점선 칸에 끌어 놓는다. 두 수가 모두 나누어떨어지면 몫 줄이 생기고, 한쪽만 나뉘면 놓은 뒤에 "9 는 나누어떨어지지 않아요". 끝났다 싶으면 '더 함께 나눌 수 없어요' — 남았으면 "아직 있어요"만(어느 수인지 말 안 함). 끝나면 왼쪽 줄 = 최대공약수, L자 = 최소공배수 |

- 공통: 판정은 손을 뗀 뒤 한 번(P3), 끄는 동안 화면을 다시 그리지 않는다(P8 — 헤드리스 실측 커밋 0회), 동시에 끄는 것은 하나(P9). 끌다가 제자리로 돌아와 놓아도 끌기로 본다. 그냥 누르기·놓친 끌기가 두 번이면 "끌기가 어려우면 눌러도 돼요"(막대 높이 누르기 · 0 한 번 누르기 · 수 → 빈칸 · 카드 → 점선 칸). 셋 다 '처음부터 다시'가 있다.
- 키보드: 막대 손잡이 ↑/↓ 토막 하나씩(Home 0·End 9), Enter 로 정하기(화면 낭독기는 조절 막대로 읽음) · 내릴 수 Enter 또는 ↓ · 조립제법 옮길 수 Enter 로 잡고 Tab 으로 빈칸, Enter 로 놓기 · 사다리 카드 Enter 로 지금 줄에 놓기. 누른 단추가 사라지면 초점은 다음 할 일(손잡이·내릴 수·옮길 수·처음부터 다시)로 간다.
- **자릿수 상한(형식 검사)** — 접은 화면 382×580 에 한 장으로 들게: 긴 나눗셈은 맨 위 줄이 소수점 포함 5칸까지(1 ÷ 7 은 되풀이까지 0 이 일곱이라 거부), 곱·뺄셈이 세 번까지(12345 ÷ 11 은 네 번이라 거부). 조립제법은 칸마다 빼기 기호 포함 3글자까지. 사다리는 함께 나누는 횟수 세 번까지(줄 넷), 공약수의 소인수가 모두 카드에 있어야 하고 서로소는 거부.
- 장면 질문·식은 장면 글이 말한다(부품 안에 문제 줄을 따로 두지 않음).

**만들어지는 검산 항목**: 긴 나눗셈은 단계마다 몫·나머지(`{n}단계 몫`·`{n}단계 나머지`) — 맨 위 줄을 그 칸까지 읽은 수를 매개변수에서 따로 만들어 sympy `divmod` 와 대조하고(앱이 단계를 이어 온 계산과 따로), 소수면 화면에 보인 몫(되풀이 마디 포함)이 `dividend/divisor` 와 같은 값인지, 정수면 `divmod` 의 몫·나머지. 조립제법은 아래 줄 몫 계수마다 `Poly(div(f, x−a)[0]).all_coeffs()`, 몫 식 `div(f, x−a)[0]`, 나머지 `div(f, x−a)[1]` 과 `f.subs(x, a)`. 사다리는 `gcd`·`lcm`(학생이 어느 카드부터 놓아도 결과는 같다 — 시험으로 확인).
