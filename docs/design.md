# 수학 다시 쌓기 — 1단계 설계 문서

작성일 2026-11-13 · 상태: **확인 대기** (확인 후 2단계 착수)

결정 사항(2026-11-13): 빌드 도구 esbuild · 화면은 방향에 따라 자동 전환 · 선택과목 3개 포함 103단원

목표: 초등 수준부터 다시 쌓아 2026학년도 수능 수학(홀수형) 수준의 문제를 스스로 푼다.

## 1. 전체 구조 한눈에

```
초등(12) ─▶ 중1(10) ─▶ 중2(10) ─▶ 중3(9) ─▶ 고1 「수학」(14) ─▶ 수학Ⅰ(10) ─▶ 수학Ⅱ(12)
                                                                                   │
                                     ┌────────────────────┬────────────────────────┤
                                     ▼                    ▼                        ▼
                               [선택] 확률과 통계(8)    [선택] 미적분(10)        [선택] 기하(8)
```

| 경로 | 단원 수 | 예상 학습 시간* | 수능에서 풀 수 있는 범위 |
|---|---|---|---|
| **A. 공통 경로** (초등 → 수학Ⅱ) | 77 | 약 192시간 | 공통 1~22번 |
| **B-확통** = A + 확률과 통계 | 85 | 약 217시간 | 공통 + 확통 23~30번 |
| **B-미적** = A + 미적분 | 87 | 약 227시간 | 공통 + 미적 23~30번 |
| **B-기하** = A + 기하 | 85 | 약 216시간 | 공통 + 기하 23~30번 |
| 선택 3과목 모두 | 103 | 약 276시간 | 46문항 전부 |

\* 개념 읽기 + 예제 + 연습문제 30개를 기준으로 잡은 대략의 시간입니다. 하루 1시간이면 공통 경로는 약 6~7개월입니다.

**처음 예상하신 "약 80단원"과의 차이**: 공통 77 + 선택 1과목(8~10) = **85~87단원**으로 거의 맞습니다. 선택 3과목을 모두 만들면 103단원, 문제 수는 **최소 3,090문제**(단원당 30)입니다.

**선택과목의 출발 시점**: 수능 시험 범위로는 셋 다 "수학Ⅱ 다음"이지만, 내용상 실제로 필요한 단원은 서로 다릅니다.
- **확률과 통계**: 고1 「경우의 수」와 중3 「대푯값과 산포도」만 끝내면 시작할 수 있습니다(수학Ⅰ·Ⅱ와 거의 무관).
- **기하**: 고1 「도형의 방정식」과 수학Ⅰ 「삼각함수의 뜻」이 필요하고, 접선 단원만 수학Ⅱ 「접선」을 씁니다.
- **미적분**: 수학Ⅰ·Ⅱ를 거의 다 써서 반드시 맨 끝에 합니다.

## 2. 커리큘럼 지도 (단원 목록)

표 읽는 법
- **ID**: 데이터 파일 이름입니다(예: `m1-linear-eq.json`). ★ 표시는 2단계에서 먼저 끝까지 만들 3개 단원입니다.
- **선수**: 먼저 끝내야 하는 단원입니다. 앱에서는 선수 단원을 다 끝내야 다음 단원에 "추천" 표시가 붙습니다(잠그지는 않습니다).
- **수능**: 직접 쓰이면 `공통 5`처럼 적고, 풀이 도구로만 쓰이면 `(공통 9)`처럼 괄호로 적었습니다. 근거는 참고 파일의 각 문항 "필요한 개념·공식"입니다.

## 4. 학습 자료 구성 (단원 하나 기준)

1. **개념** — 짧은 소제목 2~4개. 공식마다 "왜 그런지"를 한두 문장으로 붙입니다.
2. **예제 2~3개** — 참고 파일과 같은 순서로 구성합니다: 문제 → 필요한 개념·공식 → 번호 붙은 단계별 풀이 → 짚고 넘어가기 → 정답.
3. **연습문제 30개 이상** — 기초 15 / 표준 10 / 수능형 5
   - **기초**: 생성기(숫자를 바꿔 문제를 찍어내는 함수)로 만들어 "같은 유형 더 풀기"를 무한으로 할 수 있게 합니다. 단원에는 대표 15개를 고정으로 싣습니다.
   - **표준**: 직접 만든 문제입니다.
   - **수능형**: 3장 연결표의 수능 문항과 같은 개념을 쓰되, 숫자와 상황을 바꾼 새 문제입니다. 초등·중등 단원은 "수능형" 대신 그 단원 수준의 **응용(서술형)** 문제로 채웁니다(초등 분수 단원에 수능 문항을 그대로 맞출 수 없기 때문입니다).

**말투 규칙**(참고 파일 기준): "~입니다" 체, 한 단계에 계산 하나, 단계마다 짧은 제목을 붙입니다(예: "1. 밑을 3으로 통일하기"). 필요하면 "짚고 넘어가기"에 검산 방법이나 자주 하는 실수를 적습니다.

**저작권**: 문제와 해설은 모두 새로 씁니다. 참고 파일에서는 **형식과 말투만** 따르고, 문장과 숫자는 가져오지 않습니다.


- 문장으로만 답하는 문제(예: "ㄱ, ㄷ")도 `check`에 각 보기의 참·거짓을 계산하는 식을 넣습니다. 계산으로 확인할 수 없는 문제는 **싣지 않습니다**.
- 검산을 통과하지 못한 문제가 하나라도 있으면 앱 빌드도 멈추게 합니다. 그래서 검산 안 된 답이 앱에 들어갈 수 없습니다.

## 6. 앱 흐름

```
[홈: 오늘 할 일]
  ├─ 오늘 복습할 문제 N개   ─────────────┐
  ├─ 이어서 공부하기 (마지막 단원)        │
  └─ 경로 선택: 공통 / +확통 / +미적 / +기하
        │                                 │
[커리큘럼 지도]  과정별 단원 카드 · 진행률 · 선수 완료 시 "추천" 표시
        │
[단원] 개념 → 예제(단계별로 펼침) → 연습문제 목록(기초/표준/수능형)
        │
[문제 풀이]  문제 카드 + 필기 영역
   ├─ 펜으로 풀기
   ├─ 답 입력(숫자 패드 / ①~⑤ 버튼) → 정답과 자동 비교 결과 표시
   ├─ "힌트" = 필요한 개념·공식만 보기
   ├─ "풀이 보기" = 단계를 하나씩 넘김 (1단계 → 2단계 → …)
   ├─ 스스로 채점: 맞음 / 애매함 / 틀림
   └─ "같은 유형 더 풀기" (생성기가 있는 기초 문제)
        │
[오답 노트]  틀림·애매함 문제 모음 — 그때 쓴 필기도 함께 보임
```

**복습 규칙(간단한 상자 방식)**: 문제마다 상자 번호(1~5)를 둡니다.
- **맞음** → 다음 상자로 올립니다. 복습 간격은 상자 1→1일, 2→3일, 3→7일, 4→14일, 5→30일입니다. 5번 상자에서 또 맞으면 졸업합니다.
- **애매함** → 상자를 그대로 두고 내일 다시 봅니다.
- **틀림** → 1번 상자로 내리고 오답 노트에 넣습니다.

"오늘 풀 문제" = 복습일이 된 문제 + 진행 중인 단원의 새 문제(하루 목표 개수는 설정에서 정합니다. 기본 10개).

## 7. 화면 구성

판단 기준을 "기기"가 아니라 **지금 화면의 모양**으로 정했습니다. 그래서 펼치든 접든, 돌리든 저절로 맞춰집니다.

| 상태 | 화면(CSS 픽셀, 사파리 기준) | 배치 |
|---|---|---|
| 펼침 · 가로로 들기 | 951 × 585 | **좌우 2단**: 왼쪽 문제(약 40%) · 오른쪽 필기(약 60%) |
| 펼침 · 세로로 들기 | 669 × 867 | **위아래**: 위 문제(접을 수 있음) · 아래 필기 |
| 접음 (바깥 화면) | 382 × 580 | **위아래**: 위 문제(한 줄로 접힘) · 아래 필기 |

규칙: **화면 너비가 높이보다 1.2배 이상 길고 너비가 800 이상이면 좌우 2단, 아니면 위아래 1단**입니다. 펼침·세로 상태는 너비가 669라서 2단으로 나누면 문제 칸이 너무 좁아지므로 위아래로 둡니다(7-3 참고).

```
펼침 · 가로 (951×585)                       접음 · 세로 (382×580)
┌──────────────┬─────────────────────────┐  ┌──────────────────┐
│ 수학Ⅱ › 곱의…  │ [펜●●●][형광][지우개] ↶ ↷ │  │ ‹ 7/30  곱의 미분 ▾│
│ 문제 7 / 30   │ [모눈/줄] [전체 지우기]   │  │ f(x)=(x+1)(…) 일 │
│              │                          │  │ 때 f'(2)는?       │
│ f(x)=(x+1)…  │                          │  ├──────────────────┤
│ 일 때 f'(2)?  │      필기 영역            │  │ [도구 막대]       │
│              │   (손가락: 위아래 이동)    │  │                  │
│ [힌트]        │                          │  │    필기 영역      │
│ [풀이 1단계 ▸]│                          │  │                  │
│ 답 [    ] 확인 │                          │  ├──────────────────┤
│ ○맞음 △애매 ×틀림│                          │  │ 답[  ] 힌트 풀이 채점│
└──────────────┴─────────────────────────┘  └──────────────────┘
```

### 7-1. 필기 캔버스

| 요구 | 설계 |
|---|---|
| 펜만 그리기 | `pointerType === 'pen'`일 때만 획을 만듭니다. 손가락(`touch`)은 그리지 않습니다. |
| 손가락으로 이동·확대 | 캔버스에 `touch-action: none`을 걸면 브라우저 기본 스크롤이 꺼집니다. 그래서 손가락 한 개로 위아래 이동, 두 개로 확대를 **직접 구현**합니다. 화면 이동은 캔버스 위치만 바꾸는 방식이라 리렌더링이 없습니다. |
| 손바닥 무시 | 펜이 화면에 닿아 있는 동안과 펜을 뗀 뒤 약 0.5초 동안은 손가락 입력을 모두 무시합니다(글씨 쓰다 손바닥이 닿아도 화면이 움직이지 않게). |
| 촘촘한 점 | `getCoalescedEvents()`로 한 프레임 사이의 중간 점까지 받습니다. |
| 부드러운 곡선 | 점들 사이를 곡선으로 이어 줍니다. |
| 필압 없이 예쁜 글씨 | **빠르게 그으면 가늘게, 천천히 그으면 굵게**(만년필 느낌) 굵기를 바꿉니다. `pressure`가 0.5로 고정되거나 0이면 속도만 쓰고, 실제로 변하는 값이 들어오면 함께 섞어 씁니다. 획의 시작·끝은 살짝 가늘게 처리합니다. |
| 입력 지연 없음 | 그리는 동안에는 화면 프레임워크(React 등)를 전혀 거치지 않고 캔버스에 직접 그립니다. 그리는 중인 획은 위쪽 캔버스에, 끝난 획은 아래쪽 캔버스에 그리는 **2겹 구조**라서 획이 많아져도 느려지지 않습니다. |
| 도구 | 펜 3색(검정·파랑·빨강) · 형광펜(반투명, 글씨 뒤에 깔림) · 지우개(닿은 **획 전체**를 지움) · 실행 취소/다시 실행 · 전체 지우기(이것도 실행 취소 가능) · 배경 전환(없음/모눈/줄) |
| 저장 | 획은 그림이 아니라 **점 좌표 목록(벡터)** 으로 저장합니다. 문제마다 따로 IndexedDB(기기 안 저장소)에 넣고, 획 하나를 그을 때마다 자동 저장합니다. 다시 열면 그대로 보입니다. |
| 선명도·화면 변화 | 좌표를 화면 픽셀이 아니라 **"종이 좌표"**(필기 영역 너비 = 1000)로 저장합니다. 접기·펼치기·회전으로 화면 폭이 바뀌면 종이 전체가 비율 그대로 커지거나 작아질 뿐이라 글씨가 찌그러지거나 잘리지 않습니다. 캔버스는 `devicePixelRatio`만큼 촘촘하게 만들어 흐리지 않게 합니다. |
| 넓은 필기 영역 | 아래쪽 가까이 쓰면 종이가 자동으로 아래로 늘어납니다. |
| 호버 없음 | 이 기기는 펜을 띄운 상태를 인식하지 못하므로 커서 미리보기 같은 기능은 넣지 않습니다. |

### 7-2. 펜 진단 화면 (2단계에서 함께 제공)

설정 → "펜 진단"에서 펜으로 그어 보면 `pointerType`, `pressure`, `tiltX/Y`, 한 프레임당 받은 점 개수, `devicePixelRatio`, 화면 크기가 표시됩니다. 이 값을 알려 주시면 굵기 조절을 실제 기기에 맞춰 다듬겠습니다.

## 8. 기술 구성

| 영역 | 선택 | 이유 |
|---|---|---|
| 화면 | **React** + TypeScript | 화면 수가 적고 단순합니다. 필기는 React 밖에서 캔버스에 직접 그리므로 React 무게는 펜 성능과 상관이 없습니다. |
| 수식 | KaTeX를 **빌드할 때 미리 HTML로 변환**하고 글꼴은 앱에 포함합니다 | 외부 CDN 없이 오프라인에서 수식이 보이고, 폰에서 수식 변환 시간이 들지 않습니다. |
| 필기 굵기 | perfect-freehand (영국 개발자, MIT) 또는 직접 구현 | 속도 기반 굵기 조절을 이미 잘 해 주는 작은 라이브러리입니다. |
| 저장 | IndexedDB (얇은 자체 래퍼) + `navigator.storage.persist()` | 기기 안 저장. 홈 화면 앱에서 데이터가 지워지지 않도록 "영구 저장"을 요청합니다. |
| 오프라인 | 직접 쓴 서비스 워커 + 빌드 때 만드는 파일 목록 | 앱·글꼴·전체 단원 데이터를 처음 설치할 때 모두 내려받아 둡니다. |
| 검산 | Python 3 + sympy | 수식 계산을 정확하게 해 주는 도구입니다. |
| 배포 | 정적 파일 → GitHub Pages (HTTPS) | 아이폰 홈 화면 앱과 서비스 워커는 HTTPS가 필요합니다. |
| 빌드 도구 | **esbuild** (개발 서버 포함) | 2026-11-13 결정. 아래 참고 |

> ✅ **결정(2026-11-13): Vite 대신 esbuild.** 경위: 전역 원칙("중국 제작 SW 사용 금지")에 따라 의존성을 넣기 전에 만든 사람과 회사를 확인합니다. **Vite**는 중국 출신 개발자(Evan You)가 만들었고, 지금은 그가 세운 회사(VoidZero)가 관리하는 것으로 알고 있습니다. 회사 국적과 소유 구조까지는 아직 확인하지 않았습니다. 같은 계열의 vite-plugin-pwa, Vitest도 같은 이유로 보류했습니다.
> 대안: **esbuild**(미국, Figma 공동창업자 Evan Wallace 제작)로 빌드하고, 개발 서버도 esbuild 내장 기능을 씁니다(`npm run dev -- --host`는 그대로 됩니다). 테스트는 Node 내장 테스트 도구와 Playwright(마이크로소프트)를 씁니다. 기능 차이는 사용자 입장에서 없습니다.
